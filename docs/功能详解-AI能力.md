# 功能详解 · AI 能力

Knodo 的 AI 只做三件事，且都建立在**你自己的本地数据**上：写报告、找到那条任务、把笔记变成可问答的知识库。
没有 AI Key 时，这三条链路都会降级而不是报错。

> 相关文档：[笔记与知识库](功能详解-笔记与知识库.md) · [会议纪要](功能详解-会议纪要.md) · [任务与视图](功能详解-任务与视图.md)

---

## 一、AI 设置

入口在**顶部菜单栏 → AI 设置**（不在任务工具栏里）。一个弹窗分两段：

| 段 | 配置项 |
|---|---|
| 对话模型（报告 / 检索 / 纪要） | 接口预设、Base URL、模型、API Key、测试连接、清除 Key |
| 语音转写（会议录制） | 语音接口预设、地址、模型、语音 API Key、测试语音接口、清除语音 Key |

- **Key 加密存储**：通过 Electron `safeStorage`（Windows 基于 DPAPI）加密后写入 `settings` 表，
  不以明文落盘，**也不下发到渲染进程**（界面只显示「已配置 / 未配置」）。
- 语音接口与对话模型**必须分开填**：DeepSeek、Moonshot 这类纯文本服务不提供语音接口，
  复用同一把 Key 会直接失败。
- 「测试连接」只校验模型列表可达性，不产生计费。

## 二、AI 报告

基于本地任务与完成记录，自动生成 **日报 / 周报 / 月报 / 自定义范围**。

### 生成

| 项 | 说明 |
|---|---|
| 报告类型 | 日报 = 今天、周报 = 本周一至今、月报 = 本月 1 日至今；切换类型即回填日期，回填后仍可手动微调 |
| 日期范围 | **界面日期优先** —— 类型只是预置方案，手动改过就按界面的来 |
| 分组筛选 | Tom Select 多选（可搜索、已选 chips 带 ×、一键清除、按层级缩进），不选 = 全部 |
| 自定义要求 | 例如「根据任务的计划完成时间生成下个月的工作计划」，原样追加到给模型的 user 消息里；输入内容本地记忆 |

- 统计口径**含子任务**；报告层会把子任务挂到父任务下（孤儿任务标注父任务标题）。
- 分组选择器挂在 body 上，不会被可滚动容器裁掉。

### 结果

- 按 **Word 文档版式**呈现（标题层级 / 段落 / 列表 / 表格），**默认始终可编辑**；
  停止输入约 0.7s 自动保存（状态条显示「未保存 → 已保存 HH:MM」），没有「编辑 / 保存修改」按钮。
- 可在「文档视图 / Markdown 源码」之间切换。
- 导出 **Word（.docx）** 与 **Markdown**；Word 由内置的零依赖 OOXML 生成器直出（`main/docx.js`）。

### 历史记录

- **每份报告生成时即写入 `reports` 表**，不会因为生成新报告而覆盖旧记录。
- 右上角「🕘 历史记录」弹窗列出：时间 / 类型 / 范围 / 分组 / 是否含自定义要求，可查看、删除。
- 查看历史报告会载入到结果区，继续编辑会回写该条记录。

### 无 Key 降级

未配置 Key 或调用失败时，自动基于本地数据生成**结构化模板报告**（完成情况 / 进行中 / 逾期 / 小结），
并在界面明确标注「本地模板报告」。此时自定义要求不会生效，界面也会说明。

## 三、AI 检索

顶栏「🔍 AI 检索」打开一个弹窗（不切视图，当前筛选与选中任务全部保留）：
左侧是「检索历史」窄栏，右侧是结果区。输入关键词回车即检索，弹窗内展示总结与候选任务。

- **只有显式点「关闭」/ ✕ 才关窗**：点遮罩、按 Esc 都不关 —— 检索有 AI 成本，误触一下就把结果弄丢。
- **点结果也不关窗**：详情抽屉临时抬到遮罩之上（`is-over-modal`），看完一条还能接着看下一条；
  关掉抽屉回到结果列表，弹窗仍在原位。
- **空态**带四个示例关键词，点一下就检索，不用先想怎么描述。
- **每次检索自动入库**：左侧「检索历史」可回看（关键词回填 + 总结 + 命中任务快照）或单条删除。
- **结果分三态**并在顶部提示条明确区分（见下节）。
- 每条候选都展示**命中依据**（由哪个关键词、经哪条联想推导而来）与相关度条，
  例如「`ui` 缩写还原为 `界面` 命中标题」。

### 联想逻辑

关键词没精确命中时不会直接返回「未找到」，而是分层召回并按相关度排序：

| 层级 | 做法 | 说明 |
|---|---|---|
| 精确层 | SQL `LIKE` 匹配标题 / 描述 / 标签 | 命中即优先返回，不走联想 |
| 字面层 | 关键词分词后逐词比对标题、标签、描述、分组名 | 长词优先并「占掉」已匹配片段，避免 bigram 重复计分 |
| 联想层 | 同义词扩展、缩写还原、近似拼写（Damerau 编辑距离）、状态语义、时间语义 | `bug→缺陷/修复`、`ui→界面`、`wrok≈work`、`待办→未完成`、`本周→本周区间` |
| 语义层 | 配了 AI Key 时由模型在候选池内重排并给出理由 | **只重排不新增**，杜绝编造；本地零召回时用它做纯语义兜底 |

**三种结果**：

- **唯一匹配** —— 强命中（精确 / 完整包含）且明显领先第二名，或只召回 1 条且分数足够，可直接打开；
- **多个候选** —— 有候选但拉不开差距，按相关度排序请用户确认，最多 5 条；
- **确实无关联** —— 明确提示未找到，并列出**已尝试的联想方向**（只列这次真的做过的，不虚报）。

相关代码：`main/search-assist.js`（本地召回打分）、`main/ipc.js` 的 `search:ai`（分层编排）、
`main/ai.js` 的 `rankSearchCandidates`（可选语义重排）、`renderer/js/search.js`（弹窗骨架 + 三态渲染）。

## 四、语音转写（ASR）配置

采用 OpenAI 兼容的 **multipart `POST /audio/transcriptions`** 协议：

| 服务 | Base URL | 模型 | 备注 |
|---|---|---|---|
| **硅基流动 SenseVoice** | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` | 国内直连、中文优化，官方价位为**免费档**（需实名，限流固定） |
| **阿里云百炼 Qwen3-ASR-Flash** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3-asr-flash` | 国内直连，¥0.00024/秒量级，中文方言覆盖广 |
| 硅基流动 Qwen3-ASR-1.7B | `https://api.siliconflow.cn/v1` | `Qwen/Qwen3-ASR-1.7B` | 官方标价约 ¥0.00022/秒（时有限免，以官网价格页为准） |
| OpenAI Whisper | `https://api.openai.com/v1` | `whisper-1` | 需外网 |
| Groq Whisper | `https://api.groq.com/openai/v1` | `whisper-large-v3` | 需外网，速度快 |
| 本地 Whisper 服务 | `http://localhost:8000/v1` | `whisper-1` | 完全离线，须自建服务 |

**兼容性兜底**：百炼各版本兼容层对 `/audio/transcriptions` 的支持并不一致，官方主推的是
「`chat/completions` + `input_audio` base64」。因此转写遇到 **HTTP 404 / 405** 时会自动改走
`/chat/completions` 通道再试一次，用户不需要为换厂商手改地址。

> 同一个厂商地址下可能挂多个 ASR 模型，预设下拉按 **id** 定位，不会串模型。

- 「测试语音接口」校验的是模型列表可达性（不产生音频计费）；若厂商的 `/models` 只列大语言模型
  （百炼常见），会返回「连通但未见该模型」的提示而非判失败。
- 单个文件超过 24MB 会直接拒绝并提示缩短切片时长。

## 五、对话模型配置

采用 **OpenAI 兼容 `/chat/completions` 协议**，可无缝切换：

| 服务 | Base URL | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen2.5` |

**配置方式**：顶部菜单栏「AI 设置」→ 填写 Base URL / 模型 / API Key → 保存。

## 六、数据边界

- 所有任务、笔记、会议记录默认只存在本机 SQLite；**只有在你主动触发 AI 功能时**，
  相关的局部数据（报告所需的任务摘要、检索候选、待转写的音频分片）才会发给你配置的接口。
- API Key 加密后只留在主进程，渲染层拿不到明文，导出备份也不包含 Key。
- 检索的「语义重排」只在本地候选池内排序，不会新增模型臆想的任务。
