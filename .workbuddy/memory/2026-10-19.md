## 第 9 轮：标签选中态 / 统计下钻 / 报告文档化

### 1. 标签点击没有选中态（用户报的 Bug）
- **根因**：`styles.css` 里只写了 `.group-item.active`，**压根没有 `.tag-item.active` 规则**。
  JS 一边已经正确地在 `li` 上加了 `active` 类，CSS 没接住 → 点了完全没反馈。
- 修：选中 = 底色 `var(--bg-active)` + 左侧 3px 主色条（`::before`）+ `inset` 内描边 + 主色加粗文字，
  四重区分；另加 `:hover` / `:focus-visible`。
- 语义化与可达性：`role="button"` + `tabindex="0"` + `aria-pressed`，Enter/Space 可切换。
- 一致性：
  - 在统计/报告/检索/会议视图点标签会自动切回「全部任务」（这些视图不消费 tagId，
    否则会出现"点了没变化"的假死感）；
  - 顶栏新增 `#tag-filter-chip`（「标签：xxx ×」）常驻显示当前筛选，点击即清除；
  - 统计页提示「统计仍按全部任务计算」，避免选中态与数字对不上被误判为 Bug；
  - 删除标签时同步清 `settings` 里持久化的 id；侧边栏重绘时发现 id 已失效会静默清空。
- 持久化：新增 `ui:getTagFilter` / `ui:setTagFilter`（settings 键 `ui.tagFilter`），重启后保持选中。

## 第 10 轮：今日保留完成 / 拖拽不闪 / 日期控件统一 / 报告自定义提示词

### 1) 「今天」列表保留刚完成的任务
- `store.js` 新增 `recentlyDone`(Set) + `recentlyDoneDay`；`loadTasks()` 在 today 视图下**按 id 补拉**
  这些任务合并进结果。刻意不放宽 SQL —— 否则会把历史已完成任务全捞回来。

### 2) 拖拽调宽闪烁 —— 根因不是性能，是**拖拽期间的重绘**
`renderDetail()` 每次 `drawer.innerHTML = ...`：① 重播 `detailIn`（translateX 30px + opacity 0→1）
② 宽度回落到 `detailWidth` 旧值。自动保存 / 任何 IPC 刷新只要在拖拽中触发一次重绘，就"闪一下"。
- `resizing` 标志：拖拽中 `renderDetail` 置 `pendingRender` 并 return，松手后补绘。
- 只有从关闭态打开才播入场动画（`drawer.dataset.opened` → `.detail-panel.no-anim`）。
- 宽度同时写**抽屉级** `--detail-width`：面板重建直接继承，不会先跳回旧值。
- `flush()` 里同步 `detailWidth`（原来只在 endDrag 更新，重绘必然用旧值）。
- `endDrag` 按最后指针位置**同步**补写一次：窗口不可见时 rAF 被节流，最后一帧可能没落地。
- CSS：`.detail-body { scrollbar-gutter: stable }`（消除滚动条一冒一缩导致的换行抖动）、
  拖拽时 `contain: layout` + 内容区 `pointer-events: none`（防 hover 态随指针掠过一片闪动）。

### 3) 时间筛选统一为 flatpickr 范围控件

  3 组 `[data-tf]`（planStart/planEnd/completed），`DATE_RANGE_EVENT` 只绑一次（容器不换）。
- 清除 = 重建面板（`sweepDetachedRanges()` 销毁旧实例，避免 body 留孤儿日历）；顶栏按钮显示 `· N` 并高亮。

### 踩坑
- `ui.js` **重复 import** `dateRangeFieldHtml`（原 import 已含）→ `Identifier ... has already been declared`，

## 第 12 轮：今日已完成持久化 / 行内改标题 / 分组多选换库 / 报告与检索持久化

### 1. 「今天」已完成列表切走再回来就没了
- 原因：`bindStaticEvents` 的导航点击里写了 `if (view !== state.view) clearRecentlyDone()`，
  而 `recentlyDone` 只在内存里 —— 切一次视图就清空，重启更没有。
- 改：删掉导航处的清除；改成**持久化到 settings**（`ui.todayDone` = `{day, ids}` JSON），
  新增 `ui:getTodayDone` / `ui:setTodayDone`；启动时 `initRecentlyDone()` 读回，
  **只在跨天（`day !== todayStr()`）自动作废**，或用户点「隐藏已完成」才清。
  `loadTasks` 里补拉不到（已删 / 已归档 / 又被取消完成）的 id 会自动剔除并回写。

### 2. 行内改标题
- `taskItemHtml` 给 `.task-title-text` 加 `data-act="rename"`，`bindTaskListEvents` 里分发到
  `startInlineRename(span, id)`：**只替换这一行标题节点**为 `<input class="task-title-input">`，
  失焦 / 回车保存、Esc 回滚，失败时把界面还原成原标题。
- 刻意不做整表 `renderTasks()`：会丢焦点、列表闪动。

### 3. 分组多选改用第三方 Tom Select
- vendor：`renderer/vendor/tom-select/{tom-select.complete.min.js, tom-select.min.css, LICENSE}`
  （UMD 全局 `window.TomSelect`，complete 版自带 remove_button / clear_button 插件）。
- 用 `dropdownParent: 'body'`（报告区在可滚动容器里，挂容器内会被裁掉）。
- **层级缩进不要写进 option 文本**（会被搜索匹配到），改成 `data-depth="n"` ——
  Tom Select 的 `getSettings` 会 `Object.assign({}, el.dataset)`，所有 `data-*` 都进 render 的 data，
  `render.option` 里按 depth 算 `padding-left` 即可。
- 视图每次重绘都要先 `groupSelect.destroy()`，否则实例堆积。
- CSS：vendor 自带的是「结构 + 浅色默认」，主题色全部在 styles.css 里重写（`.ts-control` /
  `.ts-dropdown` / chip / × 按钮）；原自绘的 `.ms-*` 样式已删除。

### 4. 报告持久化 + 历史 + 自动保存
- db **v7 迁移**：`reports`、`ai_searches` 两张表（schemaVersion 6 → 7，导入导出同步带上）。

  点开时再 `get`，否则历史一多列表就卡。

### 5. AI 检索持久化

### 6. 冒烟测试的坑
- **rAF 会被节流**：窗口不可见时 `requestAnimationFrame` 可能 1 秒才一帧，
  拖拽宽度用固定 `sleep(140)` 会量到上一帧的旧值，于是「宽度没变 / 松手后跳变」是**假失败**。
  改成**轮询到目标宽度**（`settleAt`，最多 2s）再记录。
- `dumpFalsy` 会把「本来就应为假/零」的断言也打印出来（`tfNativeDates=0`、`tagBeforeActive=false`、
  `popClipped=null`、`subPriorityAfterEdit=0`、`persistedImmediate=0`），误导排查 → 加 `EXPECT_FALSY` 白名单。
- 上一轮冒烟把报告停在 **Markdown 源码视图**（`docMode` 是模块级变量，跨重绘保留），
  新加的报告断言必须先点 `.rp-mode[data-mode="doc"]` 切回，否则 `rp-doc` 是空的。

## 第 13 轮：接入 electron-builder，打包 Windows exe

### 结论：可打包，且**不需要 VS 编译环境**
- `better-sqlite3@13` 自带官方预编译二进制（`prebuilds/win32-x64.node`，NAPI 稳定 ABI），
  本机没有 VS Build Tools 也能打包 → 配置 `"npmRebuild": false` 跳过 rebuild。
- 产物（`dist/`）：`TODO待办-1.0.0-安装版.exe`（NSIS，中文安装界面，可改目录 + 桌面/开始菜单快捷方式）、
  `TODO待办-1.0.0-便携版.exe`（绿色版）、`dist/win-unpacked/`（可直接运行副本）。单个约 116MB
  （Electron 运行时占大头，本项目代码打进 asar 才 ~6MB）。

### 改动
- `package.json`：`build` 段（appId/productName/files/asar/`asarUnpack: node_modules/better-sqlite3/**`
  /npmRebuild:false/electronDownload 镜像/win.target=[nsis, portable]）；scripts 加
  `dist` / `dist:installer` / `dist:portable`。
- `scripts/build-win.js`：封装 electron-builder，注入 `ELECTRON_MIRROR` 与
  `ELECTRON_BUILDER_BINARIES_MIRROR`（npmmirror），否则 NSIS/winCodeSign 资源从 GitHub 下拉必超时。
- `scripts/gen-icon.js`：追加 `encodeICO()`（ICONDIR + ICONDIRENTRY + 内嵌 PNG），
  产出 `assets/icon.ico`（16/24/32/48/64/128/256）。
- `main/main.js`：便携版识别 `PORTABLE_EXECUTABLE_DIR`，userData 指向 exe 同级 `data/`，
  整个文件夹拷走即换机；安装版不受影响。
- `scripts/check-packaged.js`：打包产物体检 —— 连 CDP（Node 22 内置 WebSocket），
  查渲染层异常 + DOM 快照 + preload 接口清单。

### 踩坑（重要）
- **本会话 shell 里 `ELECTRON_RUN_AS_NODE=1`**（WorkBuddy 注入）→ 任何 Electron 程序都会退化成
  纯 Node 模式运行、随即退出，看起来像"打包失败"。命令行验证务必先
  `env -u ELECTRON_RUN_AS_NODE ...`（用户双击 exe 不受影响）。
- 用开发版 `electron.exe app.asar` / `electron.exe <解包目录>` 做诊断同样会踩上面这个坑，
  别拿它的报错当打包问题。
- `win.target` 写**对象数组**（含 artifactName）会被 schema 拒绝（"should be one of: array|null|string"），
  target 只能是字符串数组，artifactName 要放到 `nsis` / `portable` 段里。
- 沙箱的 safe-delete 会拦 electron-builder 清理缓存（批量 >50 文件）：第二次打包可能因
  删不掉旧 `win-unpacked` 或 electron 缓存目录而失败 → 用 `mv` 把旧目录挪走即可，不要硬删。
- 后台启动的 GUI 进程会随 bash 命令结束被回收，验证要**在同一条命令里**完成"启动 + 检查"。
