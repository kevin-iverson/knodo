# 截图建任务 · 实现方案与详细设计

> 状态：**已实现并发版（v2.7.0）**，验收 `npm run verify:shot`（51 项）
> 前置能力：全局快捷键、AI 对话配置、附件落盘、WYSIWYG 描述 —— 均已存在
> 数据库：**不需要迁移**，沿用 v17（视觉模型三项配置存 `settings` 键值表）

---

## 一、五个已定决策

| # | 决策 | 落到设计里 |
|---|---|---|
| 1 | **弹确认卡** | 识别结果一律先落一张可编辑的卡片，勾选后才建任务；主进程拆成 `recognize` / `commit` 两段，中间不落库 |
| 2 | **用户自己配第三方 Key** | 不内置任何 Key、不走代理；Key 本地 AES 加密存 `settings` 表 |
| 3 | **独立的视觉模型配置，且支持自定义模型名** | 新增 `ai.vision{BaseUrl,Model,Key}` 一组键，与语音转写同构；模型字段是「下拉 + 自定义」二态；**未配置时回落到对话模型** |
| 4 | **支持指定区域截图** | `Ctrl+Alt+S` 走全屏覆盖层框选，不再"截整屏"；裁剪用原图而不是预览图 |
| 5 | **`Ctrl+Alt+V` 为默认主入口，不并入插件开关** | 文档、帮助文案、验收脚本都以剪贴板路径为主路径；功能常驻，不注册 `feature.shot` |

第 3 条把原来的"一份配置两个用途"翻过来了，代价是用户要多配一组（也可以不配），收益是**主模型可以继续用 DeepSeek**——这是绝大多数存量用户的实际处境。第 4 条把"截到别人的整屏"变成"只截我要的那一块"，顺带把隐私外发的面积也缩小了。

## 二、范围

### 做（MVP）

- 全局键 `Ctrl+Alt+V`：**读剪贴板图片**（用户自己 `Win+Shift+S`）→ 识别 → 确认卡 → 建今天任务 —— **默认主入口**

- 框选后二次调整选区（拖动边角改大小）

- 连续截图追加到已有任务
- 截图 OCR 文本直读（一律进视觉模型）

### 3.3 边界原则

```
shortcuts.js ──动作──▶ main.js#dispatchShortcut
                            │
                            ▼
                       main/shot.js
                            │
              ┌─────────────┼──────────────┬─────────────────┐
              ▼             ▼              ▼                 ▼
        clipboard       shot-overlay   attachments      ai.js#recognize
        .readImage()     (框选窗口)      .importDataUrl   （视觉配置优先）
              │             │
              └──────┬──────┘
                     ▼
                压缩 + 暂存 pending
                     │
              IPC（只传缩略图）
                     ▼
            renderer/js/shot-task.js
```

- **图片字节永不双向传递**：主进程截完压好直接持有，渲染层只拿 420px 缩略图。
- **覆盖层只回 4 个数字**：`{x, y, w, h}`（CSS 像素），不回传图片。
- **`shot.js` 不 require `ipc.js`**：会成环。视觉配置的读取放在 `shot.js` 里（15 行），与 `ipc.js#getAiConfig` 保持同口径。
- **识别与落库彻底分离**：`recognize()` 只返回数据不碰 DB；`commit()` 只吃确认后的数据。

## 四、关键流程

### 4.1 剪贴板路径（`Ctrl+Alt+V`，主入口）

```
按下快捷键
  → dispatchShortcut('app.screenshotPaste')
  → shot.captureClipboard()
      clipboard.readImage() → isEmpty() ? 「剪贴板里没有图片」: 继续
  → 压缩（长边 1280 / JPEG 80）+ 暂存 + 生成 420px 缩略图
  → showWindow() + send('ui:screenshot')
  → 渲染层 openShotCard()：骨架屏 → shot:recognize → 卡片
```

这条路径**不隐藏窗口、不建覆盖层、不涉及屏幕权限**，按下去到出卡片只有一次压缩的开销。用户的实际操作是 `Win+Shift+S` 框选（系统自带的框选体验比我们做得好）→ `Ctrl+Alt+V`。

### 4.2 区域截图路径（`Ctrl+Alt+S`）

```
按下快捷键
  → shot.captureRegion()
      ① 主窗口可见 → hide()，等 200ms
      ② desktopCapturer 截当前鼠标所在屏（物理像素）
      ③ 建覆盖层窗口（覆盖 display.bounds），push 一张 JPEG q92 作背景
      ④ 用户拖拽出选区 → 返回 {x,y,w,h}（CSS px）
      ⑤ 关闭覆盖层
      ⑥ 用**原图** crop（坐标 × scaleFactor）→ 压缩 → 暂存
      ⑦ showWindow() + send('ui:screenshot')
  → 渲染层 openShotCard()（后续与剪贴板路径完全一致）
```

三个必须处理的细节：

1. **背景用压缩图，裁剪用原图**。覆盖层只需"看得清"，JPEG q92 的 4K 图约 1.2MB；而最终附件要清晰，所以 `crop()` 作用在未压缩的 `nativeImage` 上。这一步做反了，附件会糊一圈。
2. **`thumbnailSize` 是物理像素**（逻辑尺寸 × `scaleFactor`），按逻辑像素传高分屏会糊到看不清表格数字。
3. **主窗口还原放 `finally`**，并且**框选结束后一定要 `showWindow()`** —— 确认卡在主窗口里，用户如果是从别的应用按的键，主窗口此刻还是隐藏状态。

### 4.3 覆盖层窗口规格

| 项 | 值 | 原因 |
|---|---|---|
| `frame` | `false` | 无边框 |
| `transparent` | `false` | 背景是一张图，不需要真透明（真透明在部分显卡驱动上会黑屏） |
| `alwaysOnTop` | `true` + 层级 `'screen-saver'` | 普通 top 挡不住任务栏 |
| `skipTaskbar` / `resizable` / `movable` / `fullscreenable` | `false` | 一次性覆盖层 |
| `bounds` | `display.bounds` | 只覆盖鼠标所在屏 |
| `show` | 先 `false`，收到图后 `show()` + `focus()` | 空窗口闪一下很难看；不 focus 收不到键盘（Esc） |
| `webPreferences` | `contextIsolation: true` + 独立 preload | 与主窗口同一安全基线 |

覆盖层内的交互：

- 初始全屏 `rgba(0,0,0,.35)` 遮罩 + `cursor: crosshair`
- `mousedown` 记起点 → `mousemove` 实时画选区：选区本身用 `box-shadow: 0 0 0 9999px rgba(0,0,0,.45)` 挖洞，比拼四个 div 稳
- 选区边框 1px 主色，四角画 6px 的小方块
- 选区右上角实时显示 `1200 × 640`（等宽字体，超出屏边自动翻到内侧）
- `mouseup` 且两边都 ≥ 8px → 确认；否则视为取消
- `Enter` / 双击 → 确认；`Esc` / 右键 → 取消
- 拖拽中 clamp 到窗口内，允许反向拖（右往左、下往上）
- **60 秒无操作自动取消**：覆盖层是全屏置顶的，卡死会把整台机器"锁住"，这个兜底必须有

### 4.4 确认与落库

```
用户勾选 → 点「添加到今天」
  → shot:commit({ tasks: [{title, note, priority, due}] })
  → 每条：
      db.createTask({ groupId, planStart: 今天, planEnd: 今天, priority })
      attachments.importDataUrl('task', taskId, jpeg, '截图-<时间戳>')
      db.setAttachments(taskId, [entry])
      db.updateTask(taskId, { notes: '<p>备注</p><p><img src="todo-media:///..."></p>' })
  → pending = null
  → broadcastDataChanged() → 浮窗 / 日历跟上
  → 卡片关闭后回调宿主 onAdded(回执) → 主窗口补刷一次列表（见下）
```

顺序不能反：**先建任务拿 id，再落附件**（附件目录名是 `task-<id>`）。图片落盘失败不算致命（任务本身还有用），但要在返回值里如实回报 `imageErrors`。

`groupId` 沿用 `ui.lastAddGroupId`（与捕捉条、行内新建同口径），没有则取第一个清单。**一个清单都没有时直接报错，不自动建**——自动建清单会污染用户的分组树。

**广播解决不了主窗口的刷新**（11-15 修）：`ui:data-changed` 的两条守则都会把这条变更拦下来——提交那一刻确认卡的遮罩还挂在页面上（宿主 busy 判定直接 return），而卡片就在主窗口里，"添加到今天"点完窗口必然有焦点（非浮窗来源也 return）。结果是任务早已进库、列表却停在旧数据，用户得手动切一次视图才看得见。

所以刷新由卡片**显式回调**：`commit` 成功后把回执存进卡片状态，`openShotCard()` 返回的 Promise 在（确认关闭后）resolved 时调 `setShotHandlers({ onAdded })` 注入的宿主回调。宿主侧 `ui.js#refreshAfterShotAdd` 负责：`refreshAll()` → 分组筛选若会挡住新任务就放开 → 侧栏计数 → 视图是「已完成 / 归档 / 非列表视图」时 `navigateTo('today')`，否则原地 `renderTasks()`。**别改回只靠广播**：验收 `verify:shot` 有一项就守这个（去掉回调会 0 行命中）。

## 五、视觉模型：独立配置 + 回落

### 5.1 三组配置的关系

```
ai.baseUrl / ai.apiKey / ai.model            对话模型（报告、检索、润色、问答）
ai.visionBaseUrl / ai.visionModel / ai.visionKey   视觉模型（截图识别）—— 可整组不配
ai.asrBaseUrl / ai.asrModel / ai.asrKey      语音模型（转写）
```

**取值规则**（`main/shot.js#readVisionConfig` ↔ `main/ipc.js#visionView`，两处必须同口径）：

| vision 配置状态 | 结果 |
|---|---|
| `visionModel` 已填 | 用 `{ baseUrl: visionBaseUrl \|\| ai.baseUrl, apiKey: visionKey \|\| ai.apiKey, model: visionModel }` |
| `visionModel` 未填 | **整组**回落到 `{ ai.baseUrl, ai.apiKey, ai.model }` |
| 视觉这条路请求失败且属配置错误（401/403/404、Key 缺失、模型不存在） | 用上面的回落组**自动重试一次**，结果带 `degraded / degradedReason` |

**回落必须是整组的，不能逐字段**（v2.10.1 修）：用户想取消视觉配置时最常做的就是清掉模型，地址 / Key 往往还残留着。逐字段回落会拼出「智谱地址 + deepseek 模型 + 过期视觉 Key」这种必 401 的组合 —— 于是界面越"取消"，识别越报错，还退不出去。判据只认一条：**填了模型才算要用独立的视觉模型**。

同理，设置页的「视觉模型」下拉第一项是 **「不使用（用对话模型）」**（值 `__none`），选中后模型 / 地址 / Key 三样一起清。没有这一项时只能改不能清，清掉模型再打开面板还会被自动填成预设里的第一个。

**Key 复用有个坑必须处理**：`visionKey` 留空时只在 `visionBaseUrl === ai.baseUrl` 的前提下复用主 Key。地址不同还复用，必然 401 —— 报错文案要直说「视觉模型来自另一个服务商，需要单独的 API Key」，而不是把 401 原文甩给用户。

### 5.2 视觉模型预设

只列**确定能看图**的模型，避免用户在视觉分区里又踩一次"选了个文本模型"：

| 服务商 | baseUrl | 模型 |
|---|---|---|
| 智谱 GLM | `open.bigmodel.cn/api/paas/v4` | `glm-4v-flash`（免费额度大，默认）、`glm-4v-plus` |
| 通义千问 | `dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max`（默认）、`qwen-vl-plus` |
| OpenAI | `api.openai.com/v1` | `gpt-4o-mini`（默认）、`gpt-4o`、`gpt-4.1-mini`、`gpt-4.1` |
| 硅基流动 | `api.siliconflow.cn/v1` | `Qwen/Qwen2.5-VL-72B-Instruct`、`Qwen/Qwen2-VL-7B-Instruct` |
| Moonshot | `api.moonshot.cn/v1` | `moonshot-v1-8k-vision-preview` |
| Ollama（本地） | `localhost:11434/v1` | `qwen2.5vl:7b`、`llava` |

默认预设选 **智谱 GLM**：`glm-4v-flash` 是少数能免费大量调视觉的模型，截图识别是高频动作，额度决定这个功能会不会被真的用起来。

模型名以各家文档为准，目录是建议值；每个下拉末项都是「自定义…」，可以直接手填（见 §5.4）。

### 5.3 能力判定

```js
supportsImage(model):
  ① 目录精确命中 → 用它
  ② 否则按命名习惯猜：/\bvl\b|vision|llava|omni|gemini|claude-[34]|gpt-4o|gpt-4\.1|gpt-4-turbo|glm-4v|minicpm-v|step-1v/i
  ③ 都没有 → false
```

判定只在**回落路径**和**自定义模型名**上起作用。判定 false 时不发请求，文案：

> 视觉模型「xxx」看起来不支持图片，请到 设置 → AI 与语音 → 视觉模型 换一个

### 5.4 自定义模型名

「视觉模型」这一行是**下拉 + 自定义二态**，与对话模型同一套交互：

- 下拉列出当前预设的全部模型，每项右侧标注是否免费额度（如 `GLM-4V Flash（免费额度大）`）
- 末项固定「自定义…」，选中后就地换成输入框（同一行，不新增行）
- 手填过的用户，再次打开时下拉显示「自定义…」+ 输入框回填原值

这一点是决策 3 里"也支持自定义模型"的落点：**预设是省事的默认值，不是白名单**。用户接自建中转、私有部署、或厂商刚出的新模型，都能直接填名字。

### 5.5 设置页结构

```
AI 与语音
├─ 对话模型        预设 / 模型 / 地址 / Key / 连接测试
├─ 视觉模型       预设 / 模型 / 地址 / Key / 连接测试        ← 新增
├─ 语音转写        预设 / 模型 / 地址 / Key
└─ 截图建任务      识图配置（体检）/ 触发方式 / 说明        ← 新增
```

「截图建任务」分区：

```
识图配置    ✓ 使用视觉模型 GLM-4V Flash
            ⚠ 未配置视觉模型，回落到对话模型 DeepSeek Chat（不支持图片）→ [去配置]
触发方式    Ctrl+Alt+V 读取剪贴板图片（推荐）
            Ctrl+Alt+S 框选屏幕区域
            可在 设置 → 快捷键 里改键或清空
说明        截图只在你按键时截取；识别时图片会发给你配置的视觉模型服务商。
            Key 与对话模型共用同一套本地加密存储。
```

「识图配置」这行在 `saveAi()` 后就地更新（不整块重绘，避免丢焦点），值来自 `ai:saveConfig` 返回的 `vision` 字段。

## 六、确认卡详细设计

### 6.1 布局

```
┌─ 截图建任务 ───────────────────────────────── ✕ ┐
│                                                  │
│  ┌────────┐  识别到 3 项 · GLM-4V Flash          │
│  │        │  来自 框选截图 · 1200×640             │
│  │ 缩略图 │                                      │
│  │ 420px  │  「这张图是一个项目排期表」            │
│  └────────┘                                      │
│  ─────────────────────────────────────────────   │
│  ☑ 把 8 月对账单发给财务                   [高]   │
│    └ 截图里写的是 8/31 前                        │
│  ☑ 跟王工确认接口联调时间                  [中]   │
│  ☐ 整理 Q3 预算表                          [低]   │
│                                                  │
│  [全不选]                      [添加到今天]       │
└──────────────────────────────────────────────────┘
```

- 面板宽 640，最大高 78vh，列表区独立滚动（`overflow:auto` 需要确定高度链）
- 缩略图 128×80 圆角 8，点击放大到原图（`data:` URL，CSP 无 `blob:`）
- 每行：勾选框（左）、标题（可点击就地编辑）、优先级胶囊（右）
- 备注一行灰色小字，截断 80 字

### 6.2 状态机

| 状态 | 触发 | 界面 |
|---|---|---|
| `loading` | 卡片打开 | 骨架屏 + 「正在识别…」；缩略图先显示。超过 1.5s 追加「模型在读取图片，通常 5–10 秒」 |
| `ready` | 识别成功且有任务 | 任务列表，默认全选 |
| `empty` | 成功但 `tasks: []` | 「这张图里没找到需要动手的事」+ `换一张` / `我来手写` |
| `error` | 抛错 | 错误文案 + `重试`（保留同一张图）+ `换一张` |
| `submitting` | 点添加到今天 | 按钮 loading、列表禁用，防连点 |
| `done` | 成功 | 关卡片 + toast「已添加 3 条到今天」 |

**只允许显式关闭**（`closeOnMask: false`）：识别花了 5–10 秒和 token，误点遮罩就全丢了。

### 6.3 编辑能力

- 勾选：默认全选。宁可让用户取消，也不要让他一条条加。
- 标题：单击变输入框，回车确认、Esc 还原；空标题行提交时自动剔除（不弹错）。
- 优先级：点胶囊循环 `低 → 中 → 高 → 紧急 → 低`，不做下拉。
- 删除：行 hover 出 `✕`，直接从列表移除（不涉及数据库）。
- **不支持改截止日**：本期统一"今天"。截图里的日期只作为备注文本保留，**不写 `plan_end`**——写了就从"今天"里消失了，与"添加到今天的任务列表"直接冲突。

### 6.4 复用与约束

- 用现成 `openPanelModal({ closeOnMask: false, okText: '添加到今天', onMount, onSubmit })`
- 不要叠第二个 `openPanelModal`：放大图用同层浮层（`data-esc-stop`）
- 提交完走现有 `broadcastDataChanged` 链路自动重绘，**不要手动 `renderTasks()`**
- 卡片 body 是 flex 列，子项不要写 `margin: 0 auto`

## 七、IPC 契约

| 通道 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `shot:status` | — | `{ hasImage, preview, width, height, source, vision: {model, label, source: 'vision'\|'fallback', supportsImage, hasKey} }` | 卡片打开先查一次 |
| `shot:screen` | — | 同 `status` | 截屏 + 框选。取消时返回 `{ canceled: true }` |
| `shot:clipboard` | — | 同 `status` | 空图抛「剪贴板里没有图片」 |
| `shot:recognize` | — | `{ summary, tasks, model, modelLabel, source }` | 用主进程暂存的图，不接收图片参数 |
| `shot:commit` | `{ tasks }` | `{ ok, created, group, imageErrors }` | 建任务 + 存附件 + 写描述 |
| `shot:discard` | — | `{ ok }` | 关卡片时清暂存 |
| `shot:overlay-ready` | — | `{ image, width, height }` | 覆盖层窗口拉背景图（内部通道） |
| `shot:overlay-done` | `{ rect \| null }` | `{ ok }` | 覆盖层回选区（内部通道） |

`ai` 侧改动：`ai:getConfig` / `ai:saveConfig` 返回对象补 `vision: { baseUrl, model, hasKey, ... }`；新增 `ai:testVision`、`ai:clearVisionKey`。

约束：

- 所有 handler 走统一 `wrap()`，异常转 `{ __error, code }`，preload 的 `call()` 抛成可读 Error —— 项目里"点了没反应"的标准解法。
- `register()` 前逐条 `removeHandler`，防重复注册抛 `Attempted to register a second handler`。
- `ui:screenshot` 必须加进 `preload.js` 的 `on()` 白名单，否则静默不触发。
- 覆盖层用**独立 preload**，只暴露 `overlay.ready() / overlay.done(rect) / overlay.cancel()` 三个方法，不给它 `api` 全量。

## 八、数据与存储

**不改 schema。**

| 数据 | 落点 |
|---|---|
| 任务 | `tasks`（`plan_start = plan_end = 今天`） |
| 截图 | `<dataDir>/attachments/task-<id>/<uuid>_截图-<时间戳>.jpg` |

| 视觉模型 | `settings` 的 `ai.visionBaseUrl` / `ai.visionModel` / `ai.visionKey`（加密） |

图片规格：长边 1280、JPEG q80，1080p 截图约 180–280KB；框选出来的小图不放大，保持原分辨率。原图不保留。

## 十、隐私与合规

1. **截图只在你按键时截取**，没有后台/定时截屏，也不监听剪贴板（只在按键时读一次）。
2. **识别时图片会发给你自己配置的视觉模型服务商**，不是发给本应用作者。设置页用一句话写明。
3. 不想外发 → 视觉模型配 Ollama + `qwen2.5vl:7b`，全程本机。
4. 区域截图比整屏截图**只送出去选中的那一块**，这是框选顺带带来的隐私收益。
5. 本地只留存"你确认要建任务的那张图"，随附件一起；删除任务即随附件目录清掉。

## 十一、边界与已知限制

| 限制 | 影响 | 处置 |
|---|---|---|
| 框选只覆盖鼠标所在那一块屏 | 双屏用户想截另一块得移鼠标过去 | 文案说明；将来做显示器选择 |
| 框选后不能调整选区 | 手抖了要重来 | 按下 `Ctrl+Alt+S` 重截一次即可，成本低 |
| 主窗口会隐藏 200ms | 轻微闪烁 | 剪贴板路径无此问题，所以它是主入口 |
| 识别准确率不可承诺 | 偶尔漏提/多提 | 确认卡 + 可编辑 + 不写截止日 |
| 大表格类截图效果差 | 一屏几十行 | prompt 限制最多 8 条并排序；框选本身就是让用户只框关键区域 |
| 覆盖层置顶且全屏 | 极端情况会"锁住"屏幕 | 60s 超时自动取消 + Esc 随时退出 |
| 与 `Ctrl+Alt+S/V` 的系统级占用 | 注册失败 | 复用现有 `shortcuts.js` 冲突检测（注册失败明确提示换键） |
| 不并入插件开关体系（已定） | 常驻一个模块 | `shot.js` 只有 IPC + 无定时器，空闲成本≈0；不想要就清空快捷键 |

## 十三点五、实施记录（2026-11-14，已落地）

代码已全部落地，`npm run verify:shot`（真实 Electron + CDP + 本地 mock 视觉接口）45 项全绿（后续补到 51 项，含「提交后列表立刻刷新」）。

### 覆盖层的交互状态机（本次重点）

```
idle ──按下空白──▶ new ──松开（够大）──▶ selected
selected ──按下手柄──▶ resize ──松开──▶ selected
selected ──按下内部──▶ move   ──松开──▶ selected
selected ──Enter / 双击──▶ done        Esc（无拖拽时）──▶ 取消
```

四条硬规则，改这块之前先读：

1. **初始框选与二次调整共用一套 rect 与一套指针捕获**，靠 `S.mode` 分流。`pointerdown` 那一刻只判一次
   `e.target`（手柄 / `.so-move` / 空白），之后 `pointermove` 一律用捕获的 drag 描述 ——
   这样物理上不可能"拖到一半又回去重新框选"。
2. **松手一律回到 `selected`**：于是「框一次 → 拖角 → 拖边界 → 拖内部」是同一状态的多轮循环，
   没有"第二次拖动要重新开始"这种分支。
3. **手柄按「四条边」算而不是 x/y/w/h 加减**（`resizeRect`）：反向拖不会出现负宽高，越界自动夹回画布，
   始终保留 8px 最小边长。
4. **误操作保护三档**：空白处点一下（没拖动）→ 还原旧选区；调整中按 Esc → 退回这次调整前；其余 Esc → 放弃整次截图。

实时反馈：尺寸标签跟着选区左上角（放不下就翻到内侧）、底栏贴着选区上下翻（都放不下才压进选区底部），
拖动的每一帧都在改这两个 `transform`。

### 五个只有跑起来才会发现的问题

| 问题 | 现象 | 根因与修法 |
|---|---|---|
| 覆盖层没铺满屏幕 | 125% 缩放下窗口内容 1540×827，屏幕 1536×864 | `BrowserWindow` 构造参数会被系统按工作区夹一次。建完再 `setContentSize(屏幕宽高)` 读回来核对（`fitToScreen()`） |
| 附件被拉伸变形 | 裁剪比例变成「宽 1.25 / 高 1.31」 | 上一条的直接后果：`background` 被非等比拉伸。所以裁剪换算必须用**渲染层实测的 innerWidth/innerHeight**，不能用 `scaleFactor` |
| 剪贴板取不到图 | `clipboard.readImage is not a function` | **Electron 44 的 clipboard 是异步 W3C 风格**（`read()` / `item.getType(mime)`），老 API 已移除。按 MIME 挑 PNG/JPEG 块再用 `nativeImage.createFromBuffer` 复原 |
| 卡片拿不到错误码 | `NO_API_KEY / NO_VISION / STALE` 全变成普通 Error | contextBridge 跨世界复制 Error 只保留 `message / stack`，自定义 `err.code` 会被丢掉。所以 `api.shot.*` 改回**信封**（`{ok,data}` / `{ok:false,code,message}`），渲染层 `shotApi()` 还原成异常 |
| 验收脚本偶发卡死 | 按 Enter 关窗后脚本停在原地直到超时 | 窗口被销毁后那条 CDP 请求永远等不到回包。`send()` 加 8s 超时、`ws.onclose` 清空 pending、关窗的那次按键允许失败 |

### 顺手补的两处

- 视觉模型连接测试真发一张 8×8 白图：验的是"这个模型能吃图"，而不是"地址能通"。
- `换一张` 先试剪贴板（不闪屏），剪贴板没图就顺势转框选 —— 用户点它想的是"再给我一张"。

## 十四、风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 用户不理解"对话模型 / 视觉模型"要配两套 | **中高** | 第一次用不了 | 默认预设就是视觉模型（智谱 GLM）；未配置时回落 + 显式提示 + 「去配置」按钮 |
| 自定义视觉模型名拼错 | 中 | 401 / 400 | 连接测试按钮；错误原文前 300 字透出 |
| 覆盖层在高 DPI + 多屏下坐标准 | 中 | 裁歪 | 先只覆盖鼠标所在屏，坐标统一按 `display.bounds` 换算，验收用例 8/12 卡住 |
| 覆盖层把用户卡住 | 低 | 体验灾难 | 60s 超时 + Esc + 右键 + 全局键再按一次也能退出 |
| 识别质量低于预期 | 中 | 弃用 | 确认卡 + 可编辑 + prompt 限条数；框选本身就提高了输入质量 |
| 视觉模型服务商不支持 `image_url` 格式 | 中 | 部分服务商不可用 | 识别失败透出 HTTP 原文前 300 字，便于定位 |

## 附：一句话总结

**能复用的一律复用**（快捷键、附件、WYSIWYG、设置控件），**真正新的只有三件**：取图（剪贴板 + 覆盖层框选）、视觉模型这组配置、识图 prompt 与确认卡。决定成败的不是技术，是三个产品判断：**确认卡挡在最前面、视觉模型配不好要能自己解释清楚、截图永不直接入库**。
