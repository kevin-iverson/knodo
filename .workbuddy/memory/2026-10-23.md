## AI 知识库问答 + 任务多知识库引用（方案设计，未写代码）

- 产出 `docs/AI知识库问答与任务引用集成方案.md`（新增）。与已有 `docs/问题汇总与AI检索问答平台方案.md`
  的关系：那份定义 issues（问题）这条线，本方案把 issues 降为知识库的一种内置数据源，
  重点补「知识库作为一等实体 + 任务可多选引用 + 问答作用域继承」。
- 关键设计决策（后续落地要遵循）：
  - 知识库四种类型：**folder（本地目录，不复制、存绝对路径+指纹）/ upload（复制进 `<数据目录>/kb/<id>`，库里存相对路径）
    / api（Dify、RAGFlow 等，做成 provider 适配器而非让用户填通用 URL）/ builtin（issues、tasks、meetings）**；
    统一适配器接口 `describe/validate/health/enumerate/fetchContent/retrieve`，上层只见统一 Hit。
  - 主表：`knowledge_bases`、`kb_documents`（UNIQUE(kb_id, source_key)，size+mtime 指纹 + content_hash 双判定）、
    `kb_chunks`、`kb_chunks_fts`（**fts5 external content + tokenize='trigram'**，绕开中文分词器）、
    `kb_vectors`、`kb_index_state`、`task_kb_refs`（任务↔库多对多，sort_order 即人工优先级）、
    `group_kb_defaults`、`qa_sessions` / `qa_messages`（含 kb_ids 快照与 hits 快照）。
  - **一期明确不引 native 插件（sqlite-vec）**：`package.json` 现是 `npmRebuild:false` + 只 unpack better-sqlite3，
    引 native 就要 electron-rebuild + VS 工具；先用 FTS5(trigram) + 可选的内存余弦/向量 BLOB。
  - 解析依赖一律选成熟纯 JS 包：pdf-parse / mammoth / exceljs / node-html-parser；每期打包后要复量便携版 7z ≤100MB。
  - 引用读写走**独立 IPC** `tasks:setKbRefs`，不往 `db.updateTask()` 的 patch 白名单里塞。
  - 多库融合：各库各召回 → 跨库 RRF → 引用顺序/新鲜度/采纳历史做轻量加权；单库失败只降级并在答案里声明。
  - 抽层改动点（写代码时按这个清单走）：`main/db.js` MIGRATIONS 追加 v9(issues)/v10(kb) → 库已跑到 v8 且 `foreign_keys=ON`；
    `main/ipc.js` 用现成 `withDb`/`guard`；`preload/preload.js` 暴露 kb/qa，**流式要把 `qa:stream` 加进 `on()` 白名单**；
    凭据复用 `crypto.js` 加密入 settings，渲染层只拿 hasKey；
    `renderer/index.html` 侧栏加 kb/qa/issues 三个 `data-view`，`ui.js` 的 `render()` 分支同步扩；
    详情抽屉的 picker 用 Tom Select（照抄 `reports.js` 的 `dropdownParent:'body'`），
    抽屉重绘前 `picker.destroy()` + `disposeSavers()` 时序不能破。
- 落地分期 P1~P5：骨架+本地接入 → 任务多选引用 → 问答引擎（含完整降级矩阵）→ 语义增强+外部库 → 闭环沉淀与优化；
  每期必须同时过 `npm run test:db` 与 `npm run smoke`。
- 待确认：embedding 本地/云端、外部库先支持哪几家、issues 是否复用分组树、问答留存策略、是否要 OCR、
  setKbRefs 是否走独立接口（已倾向独立）。

## 笔记模块落地（Markdown 编辑 + 知识库沉淀 + 任务关联，版本 1.4.0）
- **数据层**：`main/db.js` MIGRATIONS 追加
  - v9：`note_folders`（自引用目录，同级重名由 `assertFolderName()` 应用层校验，**不加唯一索引**）/ `notes`
    （正文 `content_md` 权威，`excerpt`/`word_count`/`content_hash` 派生；`deleted_at` 软删除=回收站）/
    `note_tags`+`note_tag_map`（与任务 tags 分开）/ `task_notes`（多对多，双向 CASCADE）/
    `notes_fts`（fts5 **external content + trigram**）。
  - v10：`knowledge_bases`(内置笔记库固定 id=1,type='notes') / `kb_documents`(source_key='note:<id>') /
    `kb_chunks` / `kb_chunks_fts` / `kb_vectors`(预留)。表名与字段对齐 `docs/AI知识库问答与任务引用集成方案.md` §3。
  - 导入导出 `schemaVersion` 8→**10**；新增 notes 相关表，**不导出分块**（派生，可重建），导入后 `knowledge.indexAll()`。
- **两个 FTS 坑（已踩）**：external content 表上调用 `snippet()` 直接报 `SQL logic error`（连 bm25 查询一起废掉，
  只能静默降级 LIKE）→ 命中片段改在应用层用 `highlightOf()` 截取；trigram 查询词 < 3 字符会报错 → 应用层回退 LIKE。
- **检索/索引**：新建 `main/knowledge.js`（不依赖 Electron）：`chunkMarkdown` 按 ATX 标题切块(800/重叠120，带 heading_path)、
  `indexNote/indexAll/removeNote`、`retrieve`（同笔记最多 2 块）、`buildContext`（[n] 编号）、
  `answer`（无 AI 配置降级纯召回，reason: no-hit/no-ai/失败）。IPC：`kb:ask`/`kb:retrieve`/`kb:reindex`/`kb:stats`。
- **渲染层**：`renderer/js/notes.js`（三栏：目录/列表/编辑器，事件委托绑在常驻 `#view` 上，**必须用 WeakSet 防重复绑定**，
  否则重绘几次后一次点击触发 N 个处理器、弹窗开 N 个）；`note-picker.js`（任务侧多选，覆盖式 `taskNotes:set`）；
  `markdown-lib.js`（markdown-it，`html:false` 防 XSS，库缺失回退 `markdown.js`）。
  `detail.js` 新增「关联笔记」区块，跳转用 `await import('./notes.js')` 动态导入避免与 notes.js 静态循环依赖。
- **UI 两大坑（已踩）**：
  1. `#view` 是共享容器，任务列表 `renderTasks()` 会整块重写它的 innerHTML → 笔记视图必须检查
     `!container.querySelector('.nt-wrap')` 再重建骨架；notes 的 refresh 回调要走 `render()` 而不是 `renderTasks()`。
  2. **EasyMDE 只在「分栏」模式自动随输入重渲**，全屏预览模式改字不刷新 → `applyMode()` 后 `setTimeout(refreshPreview,30)`
     + `change` 事件 250ms 防抖重渲预览面板（它内部 active class 是 setTimeout 异步加的，必须晚一拍）。
- **依赖**：`markdown-it@14` + `easymde@2`，按项目约定 vendor 进 `renderer/vendor/`（离线），`package.json` 登记来源；
  `autoDownloadFontAwesome:false`，工具栏图标用 CSS `::after` 文字/符号兜底；CSP `img-src` 追加 `https:` 以显示外链图片。
- **删除策略**：删前弹窗列出引用任务 → 「移入回收站」（保留 task_notes、可恢复、索引摘除）/「彻底删除」
  （先删 task_notes 再删正文，返回被解除引用的任务 id）。删目录只把笔记移到上级，不删内容。
- **验证**：`npm run test:db` 173 项全过（新增 [15]~[18]：目录/标签/检索、任务关联、知识库与删除策略、备份往返）；
