# 功能详解 · 会议纪要

从「开完会只剩一耳朵印象」到「纪要 + 待办已经躺在任务列表里」，中间只需要按一次录制。
链路是：**录制 / 导入 → 语音转写 → AI 纪要 → 待办入库**。

> 相关文档：[AI 能力](功能详解-AI能力.md)（语音接口配置） · [任务与视图](功能详解-任务与视图.md)

---

## 一、录制

工具栏「⏺ 录制」打开录制设置：

| 选项 | 说明 |
|---|---|
| **仅音频**（默认） | 麦克风 + 系统声混音。Windows 下系统声走 **WASAPI 回环**，会议里对方的声音直接进来，**不需要虚拟声卡** |
| **画面 + 音频** | 从屏幕 / 窗口缩略图里挑要录的目标，适合演示类会议 |

其它设置：

- **单片时长**：5 / 10 / 15 / 30 分钟，默认 10 分钟。到点自动切开，产出多个**独立完整**的 WebM 文件
  （不是 timeslice 的增量片段，每个都能单独播放与上传），正好绕开云端 ASR 常见的单文件 25MB 限制。
- **录制中可暂停 / 恢复**，底部浮动控制条实时显示时长与已存片数。
- 录制时可以把窗口切到后台做别的事，采集不中断。

> ⚠️ **录制中不要把窗口最小化到托盘**：系统会把画面 / 采集轨挂起（仅音频模式不受影响）。

---

## 二、导入已有录音 / 录像

菜单里的「导入已有录音 / 录像」支持直接选已有媒体文件（手机录的、别的软件录的都行），
导入后走同一条转写与纪要链路。

---

## 三、语音转写

- 对接 OpenAI 兼容的 **multipart `POST /audio/transcriptions`**（Whisper 类服务）。
- 分片**顺序上传**，并把上一片的结尾作为下一片的上下文提示，减少跨片的断句错乱。
- 单文件超过 **24MB** 会直接拒绝并提示缩短切片时长。
- 兼容性兜底：遇到 **HTTP 404 / 405**（部分厂商不提供该端点）会自动改走
  `/chat/completions` + `input_audio` base64 通道再试一次，不需要为换厂商手改地址。
- 转写全文存在 `meetings.transcript`，可在「转写原文」页签里核对与编辑。

接口怎么配见 [AI 能力 · 语音转写配置](功能详解-AI能力.md#四语音转写asr配置)。

---

## 四、AI 纪要

转写完成后点「重新生成纪要」，输出结构化 Markdown：

```
## 会议主题
## 关键议题与结论
## 决议事项
## 待办事项
## 风险与遗留问题
```

- **长会议走 map-reduce**：正文超过单次上限时先分段提炼，再把分段纪要合并成一份
  （合并时明确要求去重、消除「第 x 段」痕迹），避免上下文溢出。
- 纪要存 `meetings.summary`，编辑后自动保存。
- 可导出 **Word（.docx）** 或 **Markdown**。

---

## 五、待办入库

从纪要里提取的行动项（标题 / 负责人 / 截止日期 / 优先级）显示在「待办」页签：

- **勾选后批量写入任务列表**；
- 可选「各自独立」或「挂在同一个父任务下」；
- 可指定归属分组，写入后直接出现在任务视图里。

---

## 六、文件与清理

- 音频 / 录像落在 `<用户数据目录>/recordings/<会话id>/chunk-NNN.webm`。
- 列表里「音频目录」可直接打开所在文件夹。
- **删除会议记录会一并清理对应录音目录**。
- 录音**不随 JSON 备份导出**，需要单独保留 `recordings/` 目录（会议记录里存的是绝对路径）。

---

## 七、状态流转

```
recorded（已录制）→ transcribed（已转写）→ summarized（已出纪要）
```

会议列表左侧显示标题、时间、时长、模式（仅音频 / 画面）与状态徽标；顶部可「刷新」「历史记录」。
