## AI 知识库问答 + 任务多知识库引用（方案设计，未写代码）

- 产出 `docs/AI知识库问答与任务引用集成方案.md`（新增）。与已有 `docs/问题汇总与AI检索问答平台方案.md`
  的关系：那份定义 issues（问题）这条线，本方案把 issues 降为知识库的一种内置数据源，
  重点补「知识库作为一等实体 + 任务可多选引用 + 问答作用域继承」。
- 关键设计决策（后续落地要遵循）：
  - 知识库四种类型：**folder（本地目录，不复制、存绝对路径+指纹）/ upload（复制进 `<数据目录>/kb/<id>`，库里存相对路径）
    / api（Dify、RAGFlow 等，做成 provider 适配器而非让用户填通用 URL）/ builtin（issues、tasks、meetings）**；
    统一适配器接口 `describe/validate/health/enumerate/fetchContent/retrieve`，上层只见统一 Hit。
  - 主表：`knowledge_bases`、`kb_documents`（UNIQUE(kb_id, source_key)，size+mtime 指纹 + content_hash 双判定）、
    `kb_chunks`、`kb_chunks_fts`（**fts5 external content + tokenize='trigram'**，绕开中文分词器）、
    `kb_vectors`、`kb_index_state`、`task_kb_refs`（任务↔库多对多，sort_order 即人工优先级）、
    `group_kb_defaults`、`qa_sessions` / `qa_messages`（含 kb_ids 快照与 hits 快照）。
  - **一期明确不引 native 插件（sqlite-vec）**：`package.json` 现是 `npmRebuild:false` + 只 unpack better-sqlite3，
    引 native 就要 electron-rebuild + VS 工具；先用 FTS5(trigram) + 可选的内存余弦/向量 BLOB。
  - 解析依赖一律选成熟纯 JS 包：pdf-parse / mammoth / exceljs / node-html-parser；每期打包后要复量便携版 7z ≤100MB。
  - 引用读写走**独立 IPC** `tasks:setKbRefs`，不往 `db.updateTask()` 的 patch 白名单里塞。
  - 多库融合：各库各召回 → 跨库 RRF → 引用顺序/新鲜度/采纳历史做轻量加权；单库失败只降级并在答案里声明。
  - 抽层改动点（写代码时按这个清单走）：`main/db.js` MIGRATIONS 追加 v9(issues)/v10(kb) → 库已跑到 v8 且 `foreign_keys=ON`；
    `main/ipc.js` 用现成 `withDb`/`guard`；`preload/preload.js` 暴露 kb/qa，**流式要把 `qa:stream` 加进 `on()` 白名单**；
    凭据复用 `crypto.js` 加密入 settings，渲染层只拿 hasKey；
    `renderer/index.html` 侧栏加 kb/qa/issues 三个 `data-view`，`ui.js` 的 `render()` 分支同步扩；
    详情抽屉的 picker 用 Tom Select（照抄 `reports.js` 的 `dropdownParent:'body'`），
    抽屉重绘前 `picker.destroy()` + `disposeSavers()` 时序不能破。
- 落地分期 P1~P5：骨架+本地接入 → 任务多选引用 → 问答引擎（含完整降级矩阵）→ 语义增强+外部库 → 闭环沉淀与优化；
  每期必须同时过 `npm run test:db` 与 `npm run smoke`。
- 待确认：embedding 本地/云端、外部库先支持哪几家、issues 是否复用分组树、问答留存策略、是否要 OCR、
  setKbRefs 是否走独立接口（已倾向独立）。

## 笔记模块 v1.5.0 优化（弹窗编辑 / 图片粘贴落盘 / 智能检索 / 回收站）
- **交互改造**：笔记由「三栏内嵌编辑器」改为「两栏列表 + 点笔记弹出编辑窗口」。
  `notes.js` 新增 `openNoteEditor(id)`（openPanelModal + className `modal-note-editor`，1080×90vh、
  flex 列布局、body 滚动）；`focusNote()` 改为切视图后直接弹窗。列表行内操作（编辑/归档/删除）hover 显现。
- **modal.js 两处增强**（踩坑）：
  1. 新增 `onClose` 钩子，弹窗关闭（含 Esc / 点遮罩）前 flush 自动保存器 —— 否则改完直接 Esc 会丢最后一次输入。
  2. `extraButtons` 的 handler 增加第二个参数 `close`，让「删除」这类操作能自己关掉窗口。
  3. **Promise 决议顺序坑**：弹窗内做「二选一确认」时（回收站 / 彻底删除），必须 **先 resolve('trash') 再 close()**；
     反过来的话 `onClose` 里的 `resolve(null)` 先落地，Promise 只认第一次决议 → 点了删除什么都不会发生。
- **图片落盘（复用 attachments.js）**：`main/attachments.js` 泛化出 `ownerDir(kind,id)` /
  `importInto` / `importDataUrl` / `removeOwnerDir` / `resolveMedia`，`importFile(taskId,src)` 签名不变。
  笔记图片落 `attachments/note-<id>/`，元数据进 `notes.attachments`（迁移 v11，JSON 列）。
  彻底删除笔记时 `attachments.removeOwnerDir('note', id)`。
- **todo-media:// 协议**：`main/main.js` 用 `protocol.registerSchemesAsPrivileged` + `registerFileProtocol`
  把 `todo-media:///note-12/xxx.png` 映射回附件文件（越界返回 -6）；CSP 的 img-src 追加 `todo-media:`。
  不用 file:// 是避免放开整盘 + 绕开 CSP 限制。
- **图片插入不走 EasyMDE 的 imageUploadFunction**：它内部的插入分支（P()/G()）在部分光标状态下会把
  整行替换成自身 —— 实测「图片存好了但正文没插入」。改为自己监听 `cm.on('paste'|'drop')`，
  落盘后 `cm.replaceSelection()` 插入 `![](todo-media://…)`。
- **智能检索（knowledge.js）**：`retrieve()` **变成 async**（调用方必须 await，smoke-db 已改）。
  链路：expandQuery（AI 改写 3-5 个检索词，12s 超时）→ 多路召回（分块 FTS5 + 笔记级 searchNotes→取块 +
  LIKE 兜底）→ RRF 融合（1/(60+rank)）+ 二元组字面覆盖率 + 标题/路径加权 → rerankWithAI（候选≥3，20s）
  → 每篇最多 2 块。命中带 `matchedBy`（fts/note/like）与 `coverage`，界面显示命中原因。
- **回收站**：列表页「🗑 回收站」筛选 + 行内恢复/彻底删除 + 「清空回收站」（输入「清空」确认）；
  归档笔记仍可被检索与引用（已验证）。
- **验证**：`npm run test:db` **184 项全过**（新增 [19] 图片附件 / [20] 智能检索降级）；
  CDP 驱动真实窗口 26 项 UI 检查全过（弹窗编辑、真实粘贴事件插入图片并在预览加载成功、回收站往返、
  任务关联/徽标/跳转、归档仍可检索、问答降级）。
- **测试脚本踩坑**：任务列表点 `.task-title-text` 是「就地重命名」，打开详情要 **点整行**；
  笔记选择器要点 `.np-pick-check`（点 li 不生效）；用例里的任务标题要带时间戳避免多轮数据污染。

## 笔记弹窗/主题返工（22:00–23:30）
用户反馈三件事：①主题样式异常 ②笔记要弹窗而不是整屏、弹窗更大且可缩放 ③新增笔记无效。定位结果：
- **「整屏覆盖」根因**：EasyMDE 的 `toggleSideBySide()` 默认 `sideBySideFullscreen: true`，一分栏就把
  `.CodeMirror` 变成 `position:fixed; top:50px; inset:0` 盖住整个应用（截图里的空白全屏编辑器）。
  现在**弃用 EasyMDE 的分栏/预览/全屏三件套**：弹窗内自己用 grid 做 编辑 / 分栏 / 预览（预览 = 自己
  用 markdown-it 渲染到 `#nt-preview`，带 `.markdown-body` 类复用正文字体排版），工具栏也去掉了全屏按钮。
- **弹窗只有 380px 宽的根因**：CSS 写成 `.modal-note-editor .modal`（后代选择器），而 className 是加在
  `.modal` **自身**上的 → 永远不命中。同类错误还有 `.modal-kb` / `.modal-note-delete` / `.modal-note-picker`，
  全部改成 `.modal.modal-xxx`。**以后写弹窗尺寸类必须双类选择器**（种子里早有这条注释，但只在 modal-drill 上遵守了）。
- **新增笔记「无效」**：`saver.read()` 在标题为空时返回 null → 整篇（含正文）都不落库；用户把默认标题
  「未命名笔记」清空再写正文就全丢。改为允许空标题（列表仍显示「未命名笔记」）。另：新建笔记时若处于
  搜索态会被关键词过滤掉，`createNote()` 现在自动退出搜索。
- **主题异常**：`theme:set` 以前只写库不设 `nativeTheme.themeSource` → 运行时切主题后标题栏 / 原生菜单 /
  滚动条仍是旧主题，必须重启才变。现在 handler 里同时设置 nativeTheme（'system' 也能让渲染层
  `prefers-color-scheme` 立即跟着变）。窗口加了 `backgroundColor` 防深色下白闪。
  注：Windows 的**原生菜单条**仍由系统绘制，跟应用主题无关，要彻底一致得改自绘标题栏（未做）。
- **弹窗缩放能力进 modal.js**：`openPanelModal` 新增 `showClose / headHtml / resizable / resizeKey /
  minWidth / minHeight`；`mountResize()` 用 pointer 事件实现右下角拖拽，尺寸存 localStorage
  （`modal-size:<key>`），双击手柄恢复默认，并在 `.modal` 上挂 `__toggleMax()` 供头部 ⤢ 按钮调用，
  尺寸变化时派发 `modal:resize` 事件（笔记编辑器据此 `codemirror.refresh()`）。
- 笔记弹窗默认 `min(1120px,88vw) × min(820px,84vh)`（不再 94vw/90vh，四周留白能看见列表在后面）。
  编辑区吃满高度：`.modal-body{overflow:hidden}` + `.nt-ed{flex:1;min-height:0}` + 编辑器/预览各自滚动。
- 工具栏按钮按「分栏后也能一行放下」裁剪到 12 个（去掉删除线、分隔线），并 `overflow-x:auto` 兜底。
- 验证：CDP 驱动实窗口，浅/深两套主题 × 编辑/分栏/预览截图，含拖拽缩放（778×462 → 落库）、
  最大化、窄窗口 860×560、空搜索态；`npm run test:db` 184 项全过；`npm run smoke` 全过。
