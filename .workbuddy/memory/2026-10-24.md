### 踩的坑（这次新踩）
1. **JS 的 `\W` 会吃掉汉字**：`fuzzyTokens` 里 `s.replace(/[\s\W_]+/g,'')` 把中文清光了。
   改用 `s.match(/[㐀-鿿぀-ヿ]/g)` 取 CJK 再切二元组。
2. **FTS trigram 零命中不报错**：多词带空格的查询返回 `[]` 但 `rows` 非 null，
   原来的 `if (!rows)` 不会触发降级 → 改成 `if (!rows || !rows.length)`。
3. **模糊兜底要加覆盖率门槛**（`hits/total >= 0.5`），否则搜「灰度发布」会捞到只含「发布」的笔记。
4. **「取消」的基线语义**：基线原本是「打开时的快照」，自动保存落库后再点取消会把已保存的
   内容一起撤掉（用户看到「已保存 14:53」却回到更早版本）。改成**每次保存成功后 baseline 前移**，
   取消 = 撤销自上次保存以来的改动。
5. **CDP 临时脚本不会自己退出**：WebSocket 开着会吊住 node 事件循环，必须 `process.exit(0)`，
   否则看着像「卡住」。另外 `waitFor(() => !!document.querySelector('.nt-empty'))` 会命中
   侧栏标签列表的 `.nt-empty`（「暂无标签」），断言要限定在 `.nt-col .nt-list` 内。

## 四轮修复（第三轮用户反馈：今日已完成 / Ctrl+F / 顶部搜索）

### 1. 任意视图里完成的任务都要出现在「今天完成」列表
- 根因：`store.js` 的 `noteCompletionChange()` 开头有 `if (state.view !== 'today') return false`，
  只有在「今天」视图里勾选才会被记进 `recentlyDone` —— 在「即将到期 / 全部 / 详情抽屉 /
  检索结果」里勾的都不记，切回「今天」看不到。
- 改为**记录不分视图、展示只在今天列表**（recentlyDone 本来就只是「就地保留」标记）。
- 顺带补了「连带完成」的祖先：`db.toggleTask` 在所有子任务勾完时会递归把父任务标记完成，
  这类父任务若不记进来会从今天列表里凭空消失 → 新增 `rememberCompletedAncestors(parentId)`
  沿 `parent_id` 向上（上限 8 层）补记，遇到未完成的祖先即停。调用处记得传第三个参数
  `parentId`（ui.js 的 toggleTask、detail.js 的详情勾选与子任务勾选）。

### 2. 笔记正文 Ctrl+F 查找 / 替换（新增 `renderer/js/note-find.js`）
- 匹配用 CodeMirror 自带的 `cm.getSearchCursor(query, {line:0,ch:0}, {caseFold, multiline:true})`
  —— EasyMDE 的 dist **已经打包**了 `codemirror/addon/search/searchcursor`（但未打包 `search.js`
  的面板部分、也没有 `cm-searching`/`openSearchPanel`），复用它就不需要自己写匹配，也不算重复造轮子。
- 没用官方 addon/search 的对话式面板（两级弹窗 + 英文文案），自绘浮条：查找框 + N/M 计数 +
  ↑↓ + Aa（区分大小写）+ ⇄（展开替换行）+ 替换 / 全部替换，Esc 关闭并把焦点还给编辑器。
  Enter/Shift+Enter/F3/Shift+F3 切换命中。
- 浮条插在 `.nt-dp-meta` 与 `.nt-dp-scroll` 之间（`.nt-dp` 是 flex 列），所以预览 / 分栏 /
  编辑怎么切都不会跟着某一栏跑。
- **全部替换要倒序**（`for i=n-1..0`）：正序会让后面的 {line,ch} 因前面的文本变长而错位。
- 替换后会触发 CodeMirror 的 change → debounce 260ms 的重算会把「已替换 N 处」的提示顶掉，
  所以计数位加了 1.8s 的 flash（`renderCount()` 在 flash 未过期前不改写）。
- 快捷键**必须在捕获阶段**拦：CodeMirror 的 pcDefault 键表里就绑了 `"Ctrl-F": "find"`
  （lib/codemirror.js line ~6755），虽然插件没打包不会真执行，但捕获最稳。
- Esc 也要在 `handleFindShortcut` 里处理（焦点常常仍在正文里，浮条自身收不到 keydown）。

### 3. 笔记顶部搜索框失效（典型复发 bug）
- 根因：`bindEvents(root)` 里除了事件委托，还额外给 `#nt-search` **直接挂了** addEventListener；
  而 `bindEvents` 只在骨架首次创建时执行一次（`boundContainers` WeakSet 去重），切走再回来
  时 `renderNotes` 会重建 shell（`#view` 被任务列表整块重写过），`#nt-search` 是全新节点 →
  监听永远失联，看起来就是「搜索框打不出结果」。
- 教训（写进长期约定）：**共享容器上的委托 + 逐个元素的直接绑定不能混用**，
  凡是容器会重建的视图，输入控件一律走容器级委托。
- 顺带：骨架重建后按 `keyword` 回填输入框（避免「空输入框但列表仍被过滤」），
  Enter 立即检索、Esc 清除搜索。
