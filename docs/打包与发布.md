# 打包与发布

从源码到「别人双击就能用」的 Windows 产物，以及发到 Gitee 发行版让别人直接下载。
含品牌标识、数据目录、体积控制与几个只有打包时才会踩到的坑。

> 相关文档：[开发指南](开发指南.md) · [常见问题](常见问题.md)

---

## 一、品牌与内部标识（改名前必读）

对外名称统一是 **Knodo**，来自打包配置 `build.productName`。

但 `package.json` 的 `name`（`todo-desktop`）与 `build.appId` 是**内部标识，刻意保持不变**：

- Electron 用 `name` 决定用户数据目录（`%APPDATA%\todo-desktop`）——改了会让老用户升级后看到空数据；
- `appId` 决定安装目录与卸载项。

**改品牌时只动**：`build.productName`、`nsis.shortcutName`、界面文案、图标。
启动项改名要把旧名字加进 `main/autostart.js` 的 `LEGACY_LOGIN_ITEM_NAMES`，否则老用户的自启动会变成两条。

图标由 `scripts/gen-icon.js` 用矢量 + 4× 超采样生成（三档 full / simple / tiny），
产物 `icon.png` / `tray.png` / `icon.ico` / `knodo.svg` **已随仓库提交**；
改了图标必须重新打包才会进安装版。

## 二、打包

```bash
npm run dist            # 安装版 + 便携版
npm run dist:installer  # 只出 NSIS 安装版
npm run dist:portable   # 只出便携版
```

`npm run dist` = `gen-icon` → `build-tools`（前端库 esbuild）→ `build-win.js`。
脚本只是 electron-builder 的薄封装，只出单一形态时也可直接透传参数：

```bash
node scripts/build-win.js --win nsis
node scripts/build-win.js --win portable
```

产物输出到 `dist/`：

| 文件 | 说明 |
|---|---|
| `Knodo-<版本>-安装版.exe` | NSIS 安装程序，可选安装目录、自动建桌面 / 开始菜单快捷方式，安装界面中文 |
| `Knodo-<版本>-便携版.exe` | 单文件绿色版，双击即用；数据写在 exe 同级的 `data/`，整个文件夹拷走即可换机 |
| `dist/win-unpacked/` | 未压缩的可直接运行副本（调试用） |

### 要点

- **国内镜像**：`scripts/build-win.js` 注入 npmmirror，避免从 GitHub 下载 electron / NSIS / winCodeSign 超时。
- **更好的 sqlite 不加构建链**：`better-sqlite3` 用官方预编译（`prebuilds/`），所以 `npmRebuild: false`；
  其 `.node` 必须通过 `asarUnpack` 解包到 `app.asar.unpacked` 才能被加载。
- **koffi 也要解包**：贴桌面那一档要用 `user32`（`SetParent` / `SetWindowRgn`），走 `koffi` 这个原生 FFI。
  它属于**主进程**依赖，留在 `dependencies` 是合理的（约 3MB），但必须同时进 `asarUnpack`
  （`node_modules/koffi/**/*` + `node_modules/@koromix/**/*`，预编译包在 `@koromix/koffi-win32-x64`），
  否则打包后 `require` 失败会**静默降级**成「不置顶」，看起来像功能没做。
  验证：`dist/win-unpacked/Knodo.exe` 起来后 `api.desktop.diagnostics()` 里 `attached:true parentClass:Progman`。
- **语言包裁剪**：`build.electronLanguages` 只留 `zh-CN` / `en-US`，省约 47MB。
  在禁止批量删除的受限环境（沙箱 / 严格 CI）里会中断打包，此时用
  `KEEP_ELECTRON_LOCALES=1 node scripts/build-win.js` 跳过裁剪。
- **体积预期**：首次打包需下载约 100MB 的 Electron 与 NSIS 资源（之后走缓存），
  单个 exe 约 116MB —— 这是 Electron 运行时体积，本项目代码只有约 6MB。
- **版本升级**：改 `package.json` 的 `version`，文件名与卸载条目随之变化
  （`package-lock.json` 里有两处需要同步）。

### 数据目录

- 安装版：`%APPDATA%\todo-desktop\`
- 便携版：exe 同级 `data\`（由 `PORTABLE_EXECUTABLE_DIR` 判定，且禁用开机自启）
- 任意位置：菜单「File → 存储位置」，见 [效率工具 · 存储位置](功能详解-效率工具.md#存储位置)

## 三、打包后自检

```bash
dist\win-unpacked\Knodo.exe --remote-debugging-port=9333
node scripts/check-packaged.js 9333
```

输出标题、DOM 渲染结果与渲染层异常。注意：**打包后的 exe 不接受业务命令行参数**，
所以无法用 `--smoke-test` 验证产物；需要验证时，用开发版 electron 加载
`dist/win-unpacked/resources/app.asar`。

## 四、发布到 Gitee 发行版

仓库页面「发行版」标签下的附件可供他人直接下载，无需 clone 代码。

### 1. 打包

```bash
npm run dist
```

### 2. 把产物放进 `dist/release/`

自 2.2.0 起发布形态是**两个 exe**（安装版 + 便携版），不再出 7z：

- 语言包由 `scripts/after-pack.js` 在解包完成后裁到 zh-CN / en-US，一次构建两个产物都受益
  （55 → 2，省约 40MB）；
- 两个 exe 都在 **92MiB 左右**，落在 Gitee 单附件 100MiB 以内，不需要分卷。

```bash
mkdir -p dist/release
cp "dist/Knodo-<版本>-安装版.exe" "dist/Knodo-<版本>-便携版.exe" dist/release/
```

**坑：安装版会莫名多出 13MiB。** NSIS 只要生成 blockmap（`nsis.differentialPackage`
默认开启）就会把内部 `app-64.7z` 降级成**非 solid + 普通档位**压缩，102.2MiB 直接顶穿 100MiB。
`package.json` 里已设 `build.nsis.differentialPackage: false` —— 本应用不做增量更新，
blockmap 本来也没用。

即便如此，最稳的做法仍是发布前用 `--prepackaged` 对已裁过语言包的 `win-unpacked` 各重出一遍
（同一次构建里出的便携版也会偏大约 10MiB）：

```bash
node scripts/build-win.js --win nsis     --prepackaged dist/win-unpacked
node scripts/build-win.js --win portable --prepackaged dist/win-unpacked
```

### 3. 一键发布

```bash
GITEE_TOKEN=<私人令牌> npm run release
# 或
npm run release -- --token <私人令牌>
```

`scripts/release-gitee.js` 会：读 `package.json` 版本 → 写发行说明 → 建 tag 与 Release →
逐个上传 `dist/release/` 下的附件。

- **令牌只从参数或环境变量读取**，不写入任何文件。
  生成方式：Gitee 头像 → 设置 → 安全设置 → 私人令牌（勾选 `projects` 权限）。
- 脚本具备幂等性：已存在的 tag / Release / 同名附件自动跳过；大附件上传带 3 次重试。
- 发版前把上一版产物**移出** `dist/release/`（用 `mv` 不用 `rm`），否则会被一起上传，配额很紧。
- 代码提交必须在 release **之前**：脚本按 HEAD 打 tag。
- 上传 90MB+ 约需 10 分钟，耐心等，不要中途重跑。

### 维护者备忘

| 现象 | 原因 / 处理 |
|---|---|
| 400「验证失败：文件大小已超出仓库附件配额」 | 配额 1GB 是按**仓库总量**算的，不是单文件。删旧版附件：`GET /repos/{o}/{r}/releases/{id}/attach_files` → `DELETE .../{fid}`（**路径里必须带 release id**） |
| PATCH 发行说明返回 400 | Gitee 要求 `tag_name` 必填 |
| 同名附件被传了两遍 | 附件列表接口有缓存，复查时加 `&t=<时间戳>` 绕过 |
| 私有仓库的附件匿名访问 403 | 只有有权限的登录用户能下；要公开分发需把仓库设为公开 |
| 命令行打包「一闪而过」 | 环境里有 `ELECTRON_RUN_AS_NODE=1`，先 `unset` 再跑；双击 exe 不受影响 |
| 清理 `dist/` 时被拦 | 宿主有批量删除守卫，用 `mv` 移走而不是 `rm` |
| 安装版 102MiB 超限 | `nsis.differentialPackage` 没关（blockmap 会把内部归档降级为非 solid 压缩），或没走 `--prepackaged` 复出 |
