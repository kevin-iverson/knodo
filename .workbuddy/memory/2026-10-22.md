## 冒烟失败的三个根因（都不是本轮改动引入，是历史遗留 + 测试断言写错）

1. **`feat.collapsedChildHidden=false` —— 断言写错了**：子任务行是嵌在父行 `<li class="task-item">` 内部渲染的，
   所以父行自己就带着 `.is-subtask`（来自测试建的另一个子任务的类名沿用）。断言写成
   `!document.querySelector('.task-item.is-subtask')` 永远为假。
   改为按**具体子任务 id** 判定：`!document.querySelector('.task-item[data-id="<child.id>"]')`。
2. **`r15.masksBefore=0`**：该值只是「润色前页面上残留的其它弹窗遮罩数」的提示信息，期望值本来就是 0，
   却被 `dumpFalsy` 当成失败项打印出来。加进 `EXPECT_FALSY` 白名单。
3. **`r15` 真正让它失败的是** `/润色中/.test(r15.btnText)`：按钮忙态文案早就是「改写中…」（AI 改写升级时改的），
   断言没同步。改成 `/改写中/`。**教训：`dumpFalsy` 只打印"假值"，覆盖不到 `xx === 'a'` 这种"值非假但不匹配"
   的条件，排查时优先看那些不带布尔名的断言。**

顺带修的**真实缺陷**：`bindTaskListEvents` 的 click 用 `item.dataset.id` 取 id，按钮在子任务行上时事件冒泡到父行，
会把**父任务**的展开态翻回去（点子任务箭头等于点了父任务箭头）。改为
`(btn && btn.closest('.task-item[data-id]')) || item` 取事件所属行。

验证：`electron . --smoke-test` → `SMOKE_OK`（全部 16 轮断言通过）；`npm run test:db` 142 通过。
冒烟请用独立数据目录 `--user-data-dir=/tmp/todo-smoke-x`，避免污染真实数据。

## AI 检索改造为「联想查询」（新增 main/search-assist.js）

原来 `search:ai` 只做 `db.searchTasks()` 的 SQL LIKE，字面没出现就返回空。现在改成分层召回：

1. **精确层**：先走原 LIKE，命中即优先返回（`exactHit=true`），改造前的能力原样保留；
2. **联想层**：无精确命中 → `search-assist.suggest(pool, kw)` 本地打分，Top 5；
3. **语义层**：配 Key 且非唯一匹配时，`ai.rankSearchCandidates()` 在候选池内重排（**只重排不新增**，
   本地零召回时拿最近 20 条做纯语义兜底，救回来则 `none → candidates`）。

打分通道与分值（PTS）：标题完全一致 100 / 完整包含 55 / 分词命中标题 16 / 同义词命中 12 /
近似拼写 9 / 标签 14 / 分组 10 / 描述 5-6 / 状态语义 13 / 时间语义 12；排序加成（未完成、
高优先级、近期更新）**只在已有实质命中时才加**，否则"新鲜任务"会被硬凑成候选。

分级：`unique`（强命中且领先 1.8 倍，**或**只召回 1 条且 ≥10 分——只有一条就没歧义）/
`candidates` / `none`（<8 分）。`none` 时返回 `tried[]` 说明已尝试方向，且**只记录这次真做过的**。

踩到并记录的点：

- **`db.listTasks({ status: 'any' })` 会崩**：没有任何筛选条件时 `WHERE ` 后面直接跟 `ORDER BY`，
  SQL 语法错误（既有 bug，之前没人这么调过）。已修：`where.length ? ' WHERE ...' : ''`。
- **分词要"贪心覆盖"**：不做覆盖的话「登录页样式」会同时命中 8 个 bigram token，分数虚高、
  依据列一长串。改为长 token 先匹配并把该段替换成空格。
- **编辑距离必须用 Damerau**（相邻字符交换算 1 次）：`work` 与 `wrok` 普通 Levenshtein 记 2 次替换，
  会被 4 字词的容差（1）挡掉 —— 而这恰恰是最典型的笔误。
- **缩写要先于同义词登记**：`ui` 与"界面"同在 UI 同义词组里，若同义词先 push 就会把
  `ui→界面` 标成"同义词"，依据文案不准。现在 ABBREV_MAP 先处理。
- **重排与总结必须各自 try**：放在同一个 try 里，重排失败会把总结也拖成失败。

新增冒烟第 17 轮：精确 (unique) / 缩写联想 (ui→界面) / 无关联 (none + tried) / Top5 截断 /
三态 UI 渲染。跑之前先 `api.ai.clearKey()`，否则不可达的 AI 地址会拖慢整轮。
结果仍 `SMOKE_OK`（17 轮）；`npm run test:db` 142 通过。
