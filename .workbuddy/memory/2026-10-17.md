## 计划日期范围控件改造（renderer）

- `renderer/js/controls.js`：新增单一触发器的「计划开始 ~ 完成」日期范围控件。
  - HTML：`.date-range-trigger` + 两个隐藏 input（`.dr-start-input` / `.dr-end-input`）+ `.date-range-pop` 日历面板。
  - 行为：点一次呼出日历，第 1 次点日期写 plan_start、第 2 次写 plan_end 并关闭；倒序自动交换；
    未完成的选择（只点起点就关闭）丢弃，绝不写入「半个范围」；快捷项 今天/明天/本周末/仅当天/清除。
  - 删除已无引用的 `dateFieldHtml / bindDateFields / getDateField`（双日期框旧代码）。
  - 新增导出：`validateDateRange`（含 data-required 必填开关）、`defaultDateRange`、`syncReminderWithPlanEnd`、`DATE_RANGE_EVENT`。
- `renderer/js/ui.js`、`renderer/js/detail.js`：编辑器与详情抽屉复用同一控件；保存前用 `validateDateRange` 校验，
  并把 `planStart / planEnd` 直接写进 payload。常量 `NEW_TASK_RANGE_MODE`（默认 'none'）控制新建默认值，
  `PLAN_DATE_REQUIRED` 控制是否必填（默认否）。
- `renderer/css/styles.css`：新增 `.date-range-trigger` / `.cal-quick` / `.cal-cell.preview` / `.invalid` 等样式，移除旧 `.date-field*` 与 `.editor-date` 死样式。

### 关键坑（务必记住）
- 日历面板在同一次点击里 `innerHTML` 重建后，被点击的节点会脱离文档；若用 `click` 阶段 + `field.contains(target)`
  判断"点击外部"，会把日历内点击误判为外部点击 → 点一次日期弹窗就关。已改为**捕获阶段的 `pointerdown`**判定。
- `openPops` 为模块级 Map + `drBound` 标记，避免每次列表重渲染重复挂 document 监听器。

### 验证

  start <= end、弹窗自动关闭。结果 `2026-10-01 ~ 2026-10-02` / `SMOKE_OK`。

## 第二轮修复（分组/标签新增、日历空白、抽屉拖拽调宽、子任务闪烁）

### 根因
1. **分组/标签新增"点了没反应"**：`preload` 用裸 `ipcRenderer.invoke`，主进程 handler 抛错（最典型是
   `attempt to write a readonly database`）后 Promise 被静默拒绝；渲染层 `promptAddGroup` 里 `await` 没有
   try/catch，异常被吞，界面毫无反馈。用户库（%APPDATA%/todo-desktop/todo.db）里确实一条新建分组/标签都没有。
   另：`window.prompt` 在 Electron 部分版本直接返回 null，也会表现成"没反应"。
2. **日历一大块空白**：空格子是 `<span class="cal-cell empty">`，行内元素 `height:30px` 被忽略，grid 首行
   被 auto 行高（整块网格高度 120px）撑成空白。修法：`.cal-cell` 改 `display:flex`、`.empty` 显式
   `display:block` + `height:30px`，并给 `.cal-grid` 加 `grid-auto-rows:30px`。
3. **子任务闪烁**：每次添加/勾选都 `renderDetail()` 整页重绘，且多个异步 render 并发会互相覆盖。
4. **详情栏宽度**：原本固定 420px。

### 关键实现
- `main/ipc.js`：`friendlyError()` 把 SQLite 错误翻译成中文（只读/被占用/磁盘满/重复/缺字段）；
  `withDb()` 改为 `guard()` 包裹，异常返回 `{__error}` 而不是抛。`db.isReady()/getInitError()` 新增。
- `preload/preload.js`：统一 `call(channel)` 包装，`__error` 或 invoke 拒绝都转成带 message 的 Error。
- `renderer/js/modal.js`（新增）：替代 prompt 的模态框，支持校验错误就地展示、Enter 提交、Esc 关闭。
- `renderer/js/ui.js`：`guardAction()` 统一捕获；`renderSidebar()` 拆出 `renderSidebarList()`（用 state 数据，
  不重复请求）；新增成功后**不切换筛选**，而是给条目标 `just-added` 高亮 1.2s（切筛选会让任务列表变空，
  反而像"没保存"）。
- `renderer/js/detail.js`：`renderToken` 丢弃过期渲染；`refreshSubtasks()` 只替换 `.subtask-container`；
  `syncDetailSideEffects()` 只更新父任务勾选 + 列表页；`bindResizer()` 用 Pointer Events + setPointerCapture +
  requestAnimationFrame 合并，宽度限 [360, min(860, 85vw)]，拖拽加 `html.is-resizing` 禁用选中，双击复位，
  localStorage 即时 + IPC 节流 350ms 落库（`ui:getDetailWidth` / `ui:setDetailWidth`）。
- `renderer/css/styles.css`：`.detail-panel` 宽度改 `var(--detail-width, 420px)`；新增 `.detail-resizer`、
  `.modal*`、`.choice*`、`.just-added` 动画。

### 验证
- 端到端冒烟扩展后 `SMOKE_OK`：分组弹窗新增 3→4 且列表出现、重名提示、标签新增、日历空格子 30px == 正常格 30px、
  拖拽 420→510 且重开仍 510、落库 510、边界 860/360、子任务添加后面板节点未被替换且输入框保留焦点。
- 只读库场景（chmod 444 后重新 init）实测弹窗内提示：
  "数据库当前为只读，无法写入（attempt to write a readonly database）。请检查 todo.db 所在文件夹的权限…"
- 数据层 35 通过 0 失败。

## 第三轮：即时持久化 / 子任务字段 / 展开 Bug

### 1) 编辑即时持久化
- 新增 `renderer/js/autosave.js`：`createAutoSave({delay, read, save, onStatus, onError, onConflict, onSaved})`。
  防抖 700ms；与基线 `samePayload` 比对，没变不写库；串行化（inflight 时不并发，结束后补一轮）；
  状态机 idle/pending/saving/saved/error；save 返回 null 视为 conflict。
- `ui.js`：抽出 `collectEditorPayload(ed,{quiet})`（保存按钮与自动保存共用，保证两条路径数据一致）；
  `bindEditorAutoSave()` 只挂在**编辑既有任务**上（新建任务没有 id，仍在"添加"/回车时创建）。
  `saveEditor` 对已挂自动保存的编辑器走 `flush()` + 关闭。Esc 只丢弃"尚未写入"的改动。
  失败：状态标签 `s-error` 可点击重试 + toast；冲突（任务被删）：toast + 关闭编辑器并回滚到权威状态。
- `detail.js`：`collectDetailPayload()` + `bindDetailAutoSave()`，覆盖标题/优先级/分组/日期/提醒/标签/富文本描述
  （富文本粘贴图片不触发 input，需额外监听 paste）。`saveDetail` 退化为手动 flush。
- 状态标签样式：`.editor-save-state` / `.detail-save-state`（saving 蓝、saved 绿、error 红可点）。

### 2) 子任务字段补齐
- `detail.js`：`subtaskItemHtml()` 把标题从 `<span>` 改为可就地编辑的 `<input class="subtask-title-input">`，
  行内加优先级 `<select>` 与日期范围控件；新增区加 `.subtask-new-priority` + 日期范围 + "＋添加"按钮；
  创建时传 `priority/planStart/planEnd`。`bindSubtaskAutoSave()` 逐行防抖保存。
- `main/db.js`：`listSubtasks` 排序改为与主列表一致（completed → plan_end 空值 → plan_end → priority DESC → sort_order → id）。
- `ui.js`：新增 `compareTasks()` 用于前端树内子节点排序（与 SQL 一致）。
- 筛选：子任务的 priority/plan_start/plan_end 与主任务同列存储，`listTasks` 的筛选自然生效。

### 3) 展开 Bug（真实根因，已实测复现）
- 父任务在「今天」视图可见（plan_end=今天），子任务没日期 → 被视图筛选条件过滤掉 →
  `flattenTree` 找不到子节点 → 点箭头"展开"什么都没有。诊断脚本实测 `expandedInToday:false`。
- 修法：`renderTasks()` 在 `loadTasks()` 后调用 `withExpandedChildren(tasks)`，对 `state.expandedTasks`
  中的任务显式 `api.tasks.subtasks()` 补拉子节点（递归多层）。
- 另外：分组展示改为按"最顶层祖先"的 group_id 归组，避免补拉进来的子任务因 group_id 不同跑到别的分组。
- 箭头加 `aria-expanded` + title 随状态变化。
- ⚠️ 写诊断脚本时注意：切换视图后展开状态是保留的，若之前已展开，点击一次是"收起"，会误判为 bug。

- 冲突路径（编辑中删除任务）：toast"该任务已被删除，未保存的修改已放弃"、编辑器关闭。
