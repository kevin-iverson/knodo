## 任务管理界面五项优化（已完成并跑通）

1. **标题层级**：`styles.css` `.task-title` 14px → 16px + `font-weight:500`；meta 文本 12px，层级分明。
2. **子任务计数移到标题右侧**：`ui.js taskItemHtml` 不再塞进 `.task-meta`，改为标题行内
   `.task-subtask-badge`（紧跟 `.task-title-text` 的下一个兄弟节点）。
3. **行内改名输入框宽度自适应**：`startInlineRename` 里用 canvas `measureText` 算宽度 + 2px 余量，
   上限 = 标题行宽 - 兄弟元素宽（展开箭头/子任务计数）- 12px；CSS `white-space:nowrap` 保证不换行。
4. **图片双击放大**：新增 `renderer/js/image-zoom.js`（document 事件委托，选择器
   `img.md-image / .markdown-body img / .detail-notes-editor img / .mt-markdown img`），
   markdown.js 给渲染出的 img 加 `md-image` 类；遮罩 z-index 400（弹窗 300 之上、Toast 之下），
   只用 max-width/max-height 约束，宽高比由浏览器推导；Esc / 点遮罩 / 双击图片三种关闭方式，
   Esc 用 stopPropagation 避免顺带关掉详情抽屉。
5. **侧边栏拖拽调宽**：新增 `renderer/js/sidebar-resize.js` + `index.html` 8px 把手
   （复用详情抽屉 resizer 的 Pointer Events + rAF + setPointerCapture 套路），
   180~420px 且上限受 `视口-480` 约束；宽度写 `.app` 的 `--sidebar-width` + `.sidebar` inline，
   持久化走新增的 `ui:getSidebarWidth/setSidebarWidth`（localStorage 先写，350ms 节流落库）。
6. **统计口径切换**：`db.overview(opts)` / `db.dailyTrend({range, includeSubtasks})` 把口径下推到 SQL
   （分组统计的 LEFT JOIN 条件也必须带口径，否则会丢掉"无主任务"的分组）；
   ipc/preload 传参；ui.js 新增 `statsIncludeSubtasks` + `#stats-scope` 双 chip，切换后
   `renderStats()` 整页重取，`statFilterOf` 下钻也跟随口径。

## 四项功能改造（分组同级重名 / 分组内新增任务 / 任务附件 / 数据目录可配置）

1. **分组重名改为同级作用域**：`main/db.js` 新增 `groupNameTaken(name,parentId,exceptId)` + `assertGroupName()`；
   `createGroup` / `updateGroup` 都走它。`updateGroup` 只在「名字或父级变了」时才校验（`sameParent && sameName` 短路），
   避免历史脏数据把改颜色这种无关操作卡死。`renderer/js/ui.js` `promptGroupForm.onSubmit` 的 dup 判断改为同父级比较
   （并给出「顶级分组 / 「X」下」的具体提示）。注意：**没有**加 DB 唯一索引——导入旧备份可能带同级重名，加索引会让导入/启动失败。
2. **分组行「在此分组下新增任务」**：`renderSidebarList` 的 `.group-actions` 里加 `.g-task-add`（`＋`），
   原子分组按钮改图标 `⊞` 避免两个加号；点击走 `addTaskToGroup(groupId)`：必要时切到 all 视图 → `state.currentGroup = groupId`
   → 逐级展开父分组 → `state.addingTask = true` → `render()`。默认分组靠 `taskEditorHtml` 里
   `defaultGroup = state.currentGroup` 自然带上。CSS：hover 时隐藏 `.group-count`、`gap:0`、按钮 `padding:0 2px`，
   否则 4 个按钮会把分组名挤成「工…」。
3. **任务附件**：新增 `main/attachments.js`（落盘 `<数据目录>/attachments/task-<id>/<attId>_<safeName>`，
   库里只存相对路径；200MB/文件上限；`importFile/saveAs/removeFile/removeTaskDir/absPath`）。
   `db.setAttachments()` 单独更新 attachments 列（避免被详情自动保存的 notes 覆盖）、`db.subtreeTaskIds()` 供删除时清文件。
   ipc：`attachments:pick|addPaths|open|reveal|saveAs|remove`；`tasks:delete` 顺带清子树附件目录。
   preload 暴露 `api.attachments.*` + `api.pathForFile(file)`（Electron 32+ 拖拽需 `webUtils.getPathForFile`）。
   detail.js：`attachmentsInnerHtml()` + `bindAttachmentEvents()`（事件委托 + 拖拽 drop，不整页重绘）。
   列表 meta 加 `📎 N` 角标（ui.js taskItemHtml）。
4. **数据目录可配置**：新增 `main/storage.js`（`userData/config.json` 存 `dataDir`；`probe()` 真实写测试；
   `resolve()` 不可用时回退默认并带 reason；`migrateTo()` 用 `db.backupTo()` 做 SQLite 在线快照 + 复制 attachments，
   录音不迁）。main.js：启动 `storage.resolve()` → `db.init(dir)` → `attachments.init(dir/attachments)`；
   菜单「数据存放位置…」→ `openStorageDialog()`（查看/打开/选择/恢复默认 + 复制迁移 + 重启生效）；
   回退时启动弹窗提示。对话框统一走 `msgBox()/dirDialog()`（不能给 Electron 传 `undefined` 父窗口）。
