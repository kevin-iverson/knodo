## Gitee 发行版（Release）——让用户直接下载安装包

### 官方限制（已查证 help.gitee.com）
- 发行版/仓库附件**单个 ≤100MB**（GVP 项目 200MB），每仓库总附件 ≤1GB。
- exe 直传不可行：安装版/便携版 exe 116MB 超限；NSIS 内部已 LZMA 压实，再压无收益（7z 后仍 241MB）。
- win-unpacked（401MB）→ zip(deflate) 166MB 仍超限 → 必须用 **7z(LZMA) + 瘦身**。

### 有效的瘦身组合（401MB → 94.9MB）
- 删 `locales/` 多余语言（只留 zh-CN/en-US/zh-TW，-47MB）
- 删 `dxcompiler.dll`（25MB，WebGPU shader 编译器，应用用不到；删后启动验证正常）
- 7z `-mx=9` 极限压缩：401→354MB（瘦身）→ **94.9MB**（`dist/release/TODO待办-1.0.0-win64.7z`）
- 大头：`TODO待办.exe` 236MB（Electron 44 主程序，压不动）、resources 32MB

### 工具链坑
- electron-builder 缓存自带 7za：`%LOCALAPPDATA%/electron-builder/Cache/7zip@1.0.0/7zip-win-x64-*/bin/7za.exe`
- 7za 是 Windows 程序，**不认 MSYS 的 /tmp 虚拟路径** → cd 进目录用相对路径操作
- 中断留下的半个 zip 再 `a` 会损坏（"Unexpected end of archive"）→ 先删干净重压

### 自动发布
- `scripts/release-gitee.js` + `npm run release`（GITEE_TOKEN 环境变量）：打 tag → 建 Release →
  传 `dist/release/*` 附件；已存在的 tag/Release/同名附件自动跳过；>100MB 拦截。
- Gitee API：创建 `POST /repos/{owner}/{repo}/releases`（JSON，access_token 在 body）；
  附件 `POST /repos/{owner}/{repo}/releases/{id}/attach_files`（multipart）。

## 修复：多任务详情编辑互相串改（严重数据 bug）

### 现象
列表里有 A、B 两个任务时，打开 A 详情改一下并保存，B 的内容被改成和 A 一样；
之后改任意一个，另一个也跟着变。

### 根因（不是 SQL，也不是列表数据共用引用 —— 那两处都没问题）
- 后端 `db.updateTask` 是 `UPDATE ... WHERE id = ?`，按 id 精确更新，无辜。
- `#detail-drawer` 是**常驻节点**，每次 `renderDetail` 只换 innerHTML。
  第 13 轮用 `AbortController` 作废了上一轮的**事件监听器**，但 `createAutoSave` 返回的
  保存器**从来没人 dispose**：
  - `AbortController.abort()` **取消不了已经排队的 `setTimeout` 防抖计时器**；
  - 旧保存器到期后执行 `read()` → `collectDetailPayload(drawer)` 读的是**当前抽屉 DOM**
    （此刻已经是另一个任务），却 `save()` 到**旧任务的 id** → 串改。
  - 开着 A 改一下 → 700ms 内切到 B → A 的计时器到期 → 把 B 的内容写进 A。

### 修法（renderer/js/detail.js 为主）
1. 新增保存器登记表 `activeSavers` + `trackSaver(saver, scope)` / `disposeSavers(scope)`：
   渲染前**先 flush 再 dispose**。flush 内部 `read()` 在第一个 await 之前同步取值，
   所以补写的一定是旧任务自己的数据（不丢改动，也不串到别的任务）。
2. `openDetail()` 里**先 `disposeSavers()` 再改 `state.detailTaskId`** —— 顺序反了的话
   身份校验会把这次补写判成越权而丢掉改动。
3. 抽屉 DOM 打 `data-task-id` 标记 + `isDrawerShowing(id)` 双重校验（state + DOM），
   写库前过闸：不是自己就返回 null，宁可不写也不能写错。
4. `refreshSubtasks` 换 innerHTML 前回收 `scope==='subtask'` 的保存器；
   子任务 `read()` 加 `li.isConnected` 判断。
5. `closeDetail` 改为 flush+dispose 全部，并清掉 `data-task-id`。

### 顺带修的同类问题
- `autosave.js`：save 完成后 `if (disposed) return;` —— 销毁后不再回调宿主。
- `ui.js`：`renderTasks` 换 innerHTML 前 `disposeEditorSavers()`（先 flush 再 dispose）；
  `cancelEditor` 必须 dispose 而不是只 cancel，否则 renderTasks 回收时会 flush 一次，
  把用户刚取消的内容又写回库。
- `ui.js` 行内改名改为按 id 不可变更新（`state.tasks[i] = {...}`），不再直接改 state 对象。
- `detail.js` `bindResizer` 的 `window resize` 监听带 signal（原来每次渲染都多挂一个）。

### 踩坑
- **`ELECTRON_RUN_AS_NODE=1` 会让 `npm run smoke` 用纯 Node 跑 main.js**
  （`require('electron')` 返回路径字符串 → `app` undefined → 崩在 `app.setPath`）。
  跑冒烟前必须 `unset ELECTRON_RUN_AS_NODE`。
- 冒烟脚本里 `api.tasks.create` 不会触发列表重绘，新建的任务要 `nav()` 切一次视图才出现在 DOM 里，
  否则 `rowOf(...)` 拿到 undefined 就 `Cannot read properties of undefined (reading 'click')`。

### 验证
- 新增第 14 轮冒烟断言「多任务隔离」：创建 A/B → 打开 A 改标题、**不等防抖**立刻切 B →
  等 2.5s 后校验 A/B 互不被覆盖、A 的改动保留；再在 B 里改并保存 → A 必须原样。
- `npm run smoke` → SMOKE_OK；`npm run test:db` → 98 通过 / 0 失败。
