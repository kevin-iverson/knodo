# 功能详解 · 任务与视图

Knodo 的主界面是「任务」：左侧是视图导航与分组树，中间是任务列表，右侧是按需展开的详情抽屉。
本文覆盖任务、分组、标签、筛选、排序、详情面板与统计的全部细节。

> 相关文档：[笔记与知识库](功能详解-笔记与知识库.md) · [AI 能力](功能详解-AI能力.md) · [效率工具](功能详解-效率工具.md) · [数据库设计](数据库设计.md)

---

## 一、视图

| 视图 | 说明 |
|---|---|
| 今天 | 今天到期或已逾期的进行中任务；今天刚完成的任务**就地保留**（见下文） |
| 日历 | 月 / 周尺度看每天排得下多少，拖拽排期与超载提醒（见第十一章） |
| 即将到期 | 未来一段时间内到期的任务 |
| 未完成 | 所有还没勾掉的任务（含逾期 / 未排期）。与「即将到期」互补：一个看将来，一个看欠账 |
| 全部任务 | 所有进行中与已完成任务 |
| 已完成 | 已完成但未归档的任务 |
| 归档 | 已归档任务，保留完成时间与统计口径 |
| 笔记 / AI 报告 / 会议纪要 | 侧栏里的独立功能页，进入后顶部任务工具区自动隐藏 |
| 统计 | 标题栏「日历」与「搭子」之间的入口，独立功能页（不占侧栏） |
| AI 检索 | 弹窗（不切视图），左侧检索历史 + 右侧结果 |

窗口最小尺寸 860 × 560；侧边栏可拖拽调宽（180 ~ 420px，双击把手恢复默认），宽度写入
`settings.ui.sidebarWidth`，重启后保留。

## 二、分组

- **多级子分组**：父组 ⇄ 子组无限层，侧边栏树形展示，可折叠 / 展开。
- **计数与筛选按「父包含子」计算**：点父分组 = 该分支下所有任务。
- **归属任意层级**：拖拽任务到分组、或在新增 / 编辑表单里选择分组，都能选到任意层级。
- **删除父分组**：连带删除其子分组，任务自动上移一级，不丢数据。
- **自定义颜色**：预设色 + 系统取色器自由取色（也可直接填 `#RRGGBB`）。颜色统一用于侧边栏色点、
  列表分组头、任务行分组标签与统计图表。
- **分组 / 标签通过弹窗新增**：支持重名校验（同一父级下不允许重名）与失败原因提示
  （例如数据库只读），新增后列表即时可见并高亮。

> 分组名唯一性的作用域是**同一个父分组**，且刻意不加数据库唯一索引 —— 旧备份可能带同级重名，
> 加索引会让导入直接失败；校验放在 `db.assertGroupName()`，新建与改名都会走。

## 三、任务

### 基础字段

- 标题、描述（Markdown）、优先级（低 / 中 / 高 / 紧急）、标签、分组、子任务。
- 计划时间范围：计划开始日期 / 计划完成日期，**仅年月日**，合并为**一个日期范围控件**：
  点一次只弹出一个日历面板，日历内两次点选后自动关闭并回填（起点 → 开始，终点 → 完成）；
  支持「今天 / 明天 / 本周末」快捷选项并显示跨度天数，默认留空、非必填；
  面板挂到页面顶层并做视口避让，窄容器（子任务行、详情抽屉）内也不会被裁剪。
- 完成时间：勾选完成时自动记录实际完成时间（UTC ISO），界面可见、可编辑。
- 提醒：快捷提醒（完成日期当天 09:00 / 前 1 天 18:00）+ 自定义时间，精确到分钟。

> 日期控件基于第三方 **flatpickr**（range 模式），产物已 vendor 到 `renderer/vendor/flatpickr/`
> （含中文语言包），不依赖外网运行时。

### 就地新增与编辑

新增 / 编辑任务采用「飞书式」就地交互：列表底部「添加任务」原地展开编辑器，所有字段一次展开、
不再有折叠开关。表单分三行：

1. **标题 → 优先级 → 分组 → 计划时间范围**（编辑已有任务时，行末还有「删除」）；
2. **提醒 → 标签 →（实际完成时间，仅已完成任务）→ 行末「取消 / 添加（保存）」**；
3. **备注**整宽一行，再往下是 🔁 「设为重复」块（可选）。

优先级下拉左侧有 3px 语义色条（蓝 / 橙 / 红），一眼能看出这一条有多急。

- **列表行直接显示备注摘要**：标题与元信息下方多一行灰色小字（左侧细线标识），只取纯文本、
  限 72 字后省略；备注里有图片时只留一个 `📷` 角标，不会把 base64 长串渲染到界面上。
- **点击任务标题即可行内改名**：不用打开详情页，点一下标题就地变输入框，
  失焦或回车保存、Esc 放弃；只替换这一行节点，不整表重绘。输入框宽度随输入实时自适应。
- 子任务与主任务同级：具备优先级、计划时间范围，可就地编辑并自动保存，参与列表排序与筛选。
- 列表默认收缩子任务、可展开（筛选视图下也能正常展开），显示所属父任务。

### 子任务

- 详情页树形层级展示；行内显示所属父任务。
- 任务标题右侧显示子任务进度 `☑ 已完/总数`。
- **子任务状态向上同步**：所有子任务完成 → 父任务自动完成；有子任务被取消完成 → 父任务回到未完成
  （逐级递归到根）。
- 支持拖拽排序（行首 ⠿ 手柄）；添加 / 勾选时仅局部刷新，不闪烁。
- 删除父任务会级联删除其整棵子树，并清理对应附件目录。

## 四、「今天」列表：做完了也不消失

勾选完成后任务不消失，直接打勾 / 置灰 / 添加删除线，列表上方显示「今日已完成 N 个任务」提示条。

- 标记连同**自然日**存进 `settings.ui.todayDone`（`{day, ids}`），切换标签页、甚至重启应用都还在，
  跨天自动作废。
- 点「隐藏已完成」立即移除（只影响展示，不改变视图本身的查询口径）。
- **任何视图的勾选入口都会调用 `noteCompletionChange()`**，所以在「全部任务」里勾完再回「今天」也能看到；
  连带完成的祖先任务会一起记进标记。

## 五、标签、筛选与排序

### 标签

- 标签通过弹窗新增，可设颜色；任务可挂多个标签。
- **标签筛选有明确选中态**：底色 + 左侧色条 + 主色加粗文字三重区分，支持键盘
  （Tab 聚焦 / Enter 切换）；顶栏显示当前筛选并可一键清除，切换视图与重启后均保留
  （存 `settings.ui.tagFilter`）。

### 关键词与时间筛选

- 顶栏搜索框按标题 / 描述 / 标签做即时筛选。
- **时间筛选**：按计划开始 / 计划完成 / 实际完成三组日期范围筛选，复用「添加任务」同一套
  flatpickr 范围控件（两次点选成范围、快捷选项、中文日历、面板定位完全一致）。
  顶栏按钮显示当前生效的范围组数并高亮，可一键清除。

### 排序

| 模式 | 行为 |
|---|---|
| 智能 | 未完成 → 有截止日期 → 截止日期 → 优先级降序 → 手动序号 |
| 优先级 | 按优先级降序 |
| 截止日期 | 按计划完成日期升序 |
| 手动 | 按住任务左侧 ⠿ 手柄拖动排序；拖拽时自动切到手动模式，避免「拖完又弹回原样」 |

## 六、任务详情抽屉

点击任务行（不是标题文字）打开右侧详情抽屉。

- **宽度可拖拽**（360 ~ 860px，双击手柄恢复默认），宽度自动记忆
  （`settings.ui.detailWidth`），下次打开复用。
- **拖拽过程无闪烁**：拖拽期间禁止重建面板（重绘推迟到松手）、内容区预留滚动条槽位
  （`scrollbar-gutter: stable`）、`contain: layout` 隔离重排、重绘不重播入场动画、
  松手时按指针位置同步收尾（不依赖可能被节流的 rAF 最后一帧）。
- **描述支持所见即所得编辑**：Markdown 快捷键、图片直接插入光标处。
- **描述里的图片双击可放大预览**：保持原始宽高比，再次双击 / 点击遮罩 / 按 Esc 关闭。
- **附件**：可添加文件到任务，文件本体存在 `<数据目录>/attachments/task-<id>/`，
  库里只存元数据与相对路径。
- **关联笔记**：一次关联多篇笔记（搜索 + 多选 + 顺手新建），列表项支持跳转查看与取消关联。
- **编辑即时持久化**：列表行内编辑与详情抽屉中修改任意字段，停止输入约 0.7s 后自动写入，
  无需点「保存」；失败时保留输入并可点击状态重试，任务已被删除等冲突会提示并回滚。

> 「取消」的基线是**最后一次保存成功的状态** —— 每次保存成功即前移，不会把已保存的内容一起撤销。

## 七、统计

- **口径可切换**：「仅主任务」/「含子任务」，卡片、分组、优先级、完成趋势与下钻明细实时按新口径刷新。
- **数字卡片可下钻**：总任务 / 进行中 / 已完成 / 已逾期 / 已归档，点击即列出对应任务明细，
  支持按列排序、点行跳详情，关闭回到统计页。
- **完成趋势**：近 7 天 / 近一个月 / 近半年 / 近一年。
- **分组任务量 / 优先级分布**：按当前口径实时计算，颜色取自分组自定义色。

## 八、界面与交互细节

- **排版层级**：任务标题 16px、元信息 12px，子任务进度 `☑ 已完/总数` 紧邻标题右侧；
  行内改名时输入框宽度随输入实时自适应（不换行、不遮挡右侧元素）。
- **主题**：浅色 / 深色切换（`settings.theme`），切换时同步 `nativeTheme.themeSource`，
  原生控件（菜单、对话框）跟着变色。
- **托盘常驻**：窗口「关闭」按钮默认最小化到托盘，托盘菜单可一键呼出 / 快速添加 / 退出；
  只有托盘菜单「退出」或应用内退出才真正结束进程。
- **顶部工具区**：搜索框 → 「AI 检索」→ 📝 笔记 → 导入 / 备份 / 录制 → ＋ 新建任务；
  搜索框右侧的「📝 笔记」按钮可弹出「笔记弹窗」，不离开任务就能看 / 改笔记。
  低频入口收在菜单栏：`File → 归档已完成任务` / `检查更新…`；顶格「趣味功能」放上班鼓励器与今日牛马卡，
  主题的唯一入口是设置中心。
- 非任务视图（统计 / AI 报告 / 会议纪要 / 笔记）会整排隐藏任务工具区，
  避免误点到与当前页面无关的按钮；AI 检索已改为弹窗，不换视图，工具区照旧可用。

## 九、桌面浮窗：把清单钉在桌面上

浮窗不是一个新便笺，而是**已有清单（或视图）的第二次投影** —— 同一份数据，多一个入口。

### 入口

- **主路径**：在侧边栏分组上右键 →「钉到桌面」；在「今天」「即将到期」导航项或它们的任务区上右键 →「钉到桌面」。
  已钉住的分组名 / 导航项右侧会出现 📌，菜单里也有「取消钉住 / 暂时收起 / 恢复默认位置」。
- **兜底一**：菜单栏「实用工具 → 桌面浮窗 → 已钉清单」，点一下显示 / 隐藏；还有「全部恢复默认位置」「全部收起」。
- **兜底二**：托盘右键 →「桌面浮窗 → 已钉清单」，主窗口关掉后仍能唤回。

### 窗口行为

- 一个分组一个窗、一个视图一个窗（最多 6 个），286px 宽、高度随内容（上限 520），右下角手柄可拖宽（240–460，双击恢复 286）。
- 置顶三档：始终置顶（默认）/ 仅悬停置顶 / 贴桌面（浮窗挂进桌面层，显示桌面时也在、被其它窗口盖住），在窗内「⋯」里切换。
- 拖动标题栏移动，松手贴屏幕边 12px 或与其它浮窗左边界差 8px 时自动对齐；
  位置、宽度、折叠状态都记在 `settings['tool.desktopWindows']`，下次启动原样还原。
- 不占任务栏、不抢焦点；「⋯」→「折叠为标题条」收成 42px，再点展开。
- 「⋯」→「取消钉住」关闭窗口，**任务一条不删**（浮窗只投射数据，不拥有数据）。

### 同步与异常

- 窗内勾选 / 取消勾选 / 新增待办：立即写库，主窗口在未聚焦时自动重绘（约 1 秒内）。
  勾完的任务**留在原位只变灰**，不跳到列表末尾 —— 否则连点两条会误勾。
- 主窗口改数据时，浮窗只重拉自己这个清单，滚动位置不动。
- 分组被删除：浮窗显示「该清单已删除」，3 秒后自动关闭并移出已钉列表。
- 视图投影没有「被删除」这回事：「今天」= 进行中且计划完成日 ≤ 今天，「即将到期」= 进行中且计划完成日 ≥ 今天，口径与主窗口完全一致；
  在「即将到期」窗里新增的待办默认排到今天（日期留空的任务本来就不会出现在这个视图里）。
- 数据库不可用：显示「数据未就绪，点击重试」，不空白、不弹错。

## 十、番茄钟：每一格留下一句话

核心主张：**番茄的产物不是时长，是一句话**。市面上的番茄钟都在统计「今天专注了几个 25 分钟」，
而第二天坐到桌前真正需要知道的是「昨天这件事我做到哪了」。所以这里把番茄钟做成任务的推进记录，计时只是产出那句话的手段。

### 怎么用

1. 悬停任务行 → 右侧出现 **▶**（20×20，不悬停不出现，避免列表变吵）→ 点一下开钟。
   旁边的 `30'` 是时长，点一下在 15 / 30 / 45 分钟之间循环，记在 `localStorage['knodo.focusDurationSec']`。
2. 专注中：行首出现 14px 进度环（与勾选框同尺寸），行尾是剩余时间和「结束」，整行淡主色描边。
   点进度环或 `Ctrl+Enter` 暂停 / 继续；暂停时环与时间转灰。
3. 跑满 → 行下方就地展开收尾条（浅底色、无阴影，不像是又一层浮层），输入框已聚焦，
   问句是「做到哪了？」。`Enter` = 今天到这，`Esc` = 跳过，`再来一格` = 结算后立刻同任务重开。
4. 结算后：`● 11-03 10:25 一句话`（整格）或 `◐ …`（半格）追加到任务备注末尾；
   详情右侧「专注 🍅」按时间倒序列出每次会话（标记 + 那句话 + 实际分钟数）。

### 三种结局

| 结局 | 触发 | 记几格 | 标记 |
|---|---|---|---|
| `full` | 跑满计划时长 | 1 | `●` |
| `partial` | 手动结束，且已投入 ≥ 8 分钟 | 0.5 | `◐` |
| `interrupted` | 暂停 > 3 分钟 / 真离开 > 3 分钟 / 休眠睡过头 | 0.5（带原因） | `◐` |
| 不记录 | 手动结束且 < 8 分钟 | — | 直接删掉会话行 |

- **8 分钟是硬下限**，不随时长设置浮动（规则一跟着设置变，用户就觉得没有规则）。
- **不惩罚中断**：惩罚中断的番茄钟最后会被用户整个关掉，所以被打断也照样留半格和那句原因。
- **「离开」不是「失焦」**：切到 IDE / 浏览器继续干活时窗口是失焦的，计时必须照常走；
  只有「没有任何 Knodo 窗口聚焦 **且** 系统连续 3 分钟无键盘鼠标输入」才结算为被打断。
- 休眠：挂起时先结算睡眠前那段，唤醒后按 wall clock 对账 —— 睡过 2 倍计划时长记半格并标「休眠中断」，
  跨过结束点记整格，都没跨过就接着走（睡眠时间不计入专注）。
- 崩溃 / 强杀：启动时 `reconcileOnStartup()` 对账 `ended_at IS NULL` 的残留行，≥8 分钟记半格，否则删掉；
  正常退出时 `handleWillQuit()` 把进行中的番茄记半格，并在下次启动提示「上次有一个 N 分钟的番茄，已记上」。

### 显示规则

- 任务标题右侧：格数圆点，最多 3 个 + 「+N」（`●●●+2`），整格主色、半格琥珀色。
- 顶栏：「今天 N 格」（等效格数，半格算 0.5），**不显示目标值** —— 不制造「今天还差 6 格」的压力。
- 连续专注软提示：第 3 格（90 分钟）提示「起来走两步」，第 4 格起建议换任务；只提示，不强制休息。
- 桌面浮窗里，正在专注的那一行显示进度环 + 倒计时（只读，不给开钟 / 收尾入口）。

### 边界

- **不支持「自由专注」**：`focus_sessions.task_id` 是 `NOT NULL`，不挂任务的计时最后只剩一个数字，
  会削弱「番茄必须挂任务」这个地基；将来真要做，再补一个「收件箱级」的兜底。
- **不改任务结构**：番茄只往备注追加一行，不动分组、日期、优先级。
- **删任务不删记录**：`task_id` 继续指向已不存在的 id，统计里仍算数，展示降级为「已删除的任务」。
- 收尾条只渲染在「刚结束的那个任务所在的行下」：如果当前视图里没有这条任务（比如切到了别的分组），
  会话保持 `done` 态，切回该任务所在视图或点「结束」后照常结算，不会静默丢数据。

## 十一、日历：格子回答的不是「有什么」，是「排得下吗」

任务列表按分组平铺，回答的是「有哪些事要做」；日历按天铺开，回答的是**「今天还塞得进去吗」**。
同一份 `plan_start / plan_end`，两个尺度：侧栏「今天」是日历里今天那一格的放大版，点日历里某天即可下钻回列表那一天。

### 入口与尺度

- 标题栏「🗓 日历」（主区段左端，与「统计」「搭子」同组）是一级入口；`Ctrl+Alt+M` 直接进日历，**再按一次回到进入前的列表**（记住的是 `lastListView`，不一定是「今天」）。
- 月 / 周只在日历内部右上角的分段控件里切换，`settings['tool.calendar'].view` 记住上次的级别，下次进来还是它。
- 日历态下顶栏工具（搜索、AI 检索、笔记、新建）都在，筛选栏隐藏 —— 别的视图的筛选条件不该偷偷影响日历看到的东西。

### 负载模型

| 优先级 | 权重 |
|---|---|
| 低 | 0.5 |
| 中 | 1 |
| 高 | 2 |
| 紧急 | 3 |

- 每天的负载 = 当天所有未完成任务的权重之和；**跨天任务按天数均摊**（11/02–11/06 的紧急任务每天 0.6）。
- 容量默认 **6**，可在 4–10 之间调（`capacity`）。6 的含义是「一天扛 6 个中等任务」，不是一个精确工时。
- 负载率决定格子的形态：`< 60%` 有余量（浅蓝）／`60–100%` 接近满（主色）／`≥ 100%` 超载（红条 + 红框 + 溢出角标），`> 140%` 加斜纹表示严重超载。
  超载同时用**颜色 + 边框 + 角标**三种方式表达，不只靠颜色。
- 已完成任务默认不显示（`showCompleted` 打开后降为 40% 透明度），也不计入负载。

### 排期：拖就是全部操作

- 左栏「待安排」= 没有计划日期的进行中任务。拖到某个格子 = 从那天起排期；跨天任务从落点开始连着占几天。
- 拖动过程中，目标格子实时画出**预测负载**并显示「放下后 4.2 / 6」——松手之前就知道后果。
- 落到已满的一天会弹「这一天会超载」，两个选择：**仍然放入**（尊重你的判断）或 **放到下一个空日**
  （往后找第一天「当前负载 + 本条 ≤ 容量 × 60%」，最多找 60 天）。
- 把格子里的任务拖回左栏 = 取消排期（`plan_start / plan_end` 置空，任务回到待安排）。
- 拖到网格左右边缘停 0.8 秒自动翻上 / 下个月，跨月排期不用切两次。
- 每次改期都有 5 秒撤销条（`撤销` / `✕`），撤销恢复的是改之前的 `plan_start`、`plan_end` 与优先级。

### 看与改

- **点某天 → 右栏当日面板**：当日负载、负载条、按分组列出的任务清单。清单里可直接勾选完成（选中今天及以后时）、
  改优先级（下拉）、点 `→` 延期一天。点格子只换选中态与右栏，**不跳页、不滚动**。
- 格子内最多 2 条任务卡，更多的折成「+N」，点开即右栏的完整清单。任务卡是「优先级色条 + 标题」，
  勾选框悬停才出现（避免挤掉标题宽度）。
- 跨天任务在续日的卡片前带 `↳`，**标题照常显示**；超期任务卡带红点。
- 右键任意卡片：打开详情 / 改优先级 / 延期一天 / 移出排期 / 标记完成；双击卡片直接开详情。
- **超期欠账只汇总在「今天」格**：一颗红徽标（条数）+ 一行「⚠ 积压 N 条（最早 11-01）」。
  点开右栏列出每条「已超期 N 天」，可逐条「改到今天」，也可「全部改到今天」。
- 底部三行：图例（区分四种负载形态）、整月负载趋势条（每天一根，悬停看具体数值）、
  「本月 N 天有安排 · M 天超载 · 平均负载 X%」+「调整每日容量」。
- 周视图是 7 列竖排（不是时间轴）：任务标题完整展开，用来「看这一周到底压了什么」。

### 容量与偏好

`设置 → 实用工具 → 日历视图` 或日历底部「调整每日容量」：

| 项 | 说明 |
|---|---|
| 每日容量 | 4–10，默认 6 |
| 每周起始日 | 周一（默认）/ 周日 |
| 显示已完成任务 | 关闭（默认）/ 开启（40% 透明度，不计负载） |

容量只是提醒，**不会阻止你往超载的日子排任务** —— 工具负责把后果摆出来，不替你决定哪天加班。

### 与其它模块的关系

- **零迁移**：日历不新增表也不新增字段，读的就是任务已有的 `plan_start / plan_end`（`YYYY-MM-DD` 字符串）。
  因此备份、导入导出、AI 报告、统计的口径天然一致 —— 在日历里改的日期，就是「即将到期」看到的日期。
- 勾选完成走与列表同一个入口（`tasks.toggle` + `noteCompletionChange`），所以「今日已完成」的保留逻辑在日历里同样成立。
- **过去的日期完成态只读**（`isPastDay()`）：格子里与右栏的勾选框都带 `is-locked`，点下去只给提示、不改库。
  理由是在日历上改历史看不出代价 —— 一次性任务的归属日会被挪动，重复事项那一格的点击等于删掉
  `recurrence_completions` 里的历史打卡。要改历史请走任务列表 / 详情，或「重复事项」的打卡日历。
  验收脚本：`npm run verify:calendar`。
- 子任务跟随父任务上日历，不单独占格（一个父任务下 5 个子任务散在一周里会失真，等真实使用数据再定）。
- 唯一设置项存在 `settings['tool.calendar']`，随完整备份一起走。

### 边界

- **不做时间轴**：计划日期只有年月日，画到小时就是编。
- **不做工时估算**：负载单位对用户是隐形的（只说 `6.5 / 6`），要求填预估时长会劝退，且填写率未知。
- **不阻止超载**：超载只提示。惩罚性的拦截最后会被用户绕过或关掉整个功能。
- 窄窗口（≤ 1080px）右栏整体收起，周视图因此只看不拖，排期回月视图做。

## 十二、重复待办与习惯：一条任务，按规则反复出现

### 怎么建

- 新建 / 编辑任务 → 编辑器里的「🔁 设为重复」；任务详情抽屉 →「重复与提醒」区（可就地改规则与提醒时间）；管理面板 →「＋ 新建重复事项」。
- 频率：`每天` / `每周`（可多选星期）/ `每月`（可多选日期，支持月末）/ `每个法定工作日`；`每隔 N 天/周/月` 由间隔控制。
- 起止日期、提醒时间（可提前 N 天）、完成日偏移都在同一块配置，右上有「接下来几次」预览。默认规则是「每个法定工作日 + 09:00 提醒」。
- 勾「作为习惯打卡」即成为习惯项（💪 徽标）。
- **已有的一次性任务也能就地转重复**：先保存原任务再建规则，附件、关联笔记、子任务、完成状态都保留，不会多出一条同名任务。

### 只有一条任务

规则存在 `recurring_rules`，与 `tasks` 里的**一条**任务 1:1（`recurring_rules.task_id`）。
这条任务的 `plan_start / plan_end / reminder_at / completed` 始终表示「当前这一次发生」：

- 调度器在启动、每 30 分钟、跨自然日时调 `rollRecurringTask()`，把这一行推进到下一次应发生日，
  同时按打卡记录刷新完成态、重置提醒标记。因此「今天 / 即将到期 / 全部任务 / 日历 / 统计 / 提醒」
  全部继续用原来的过滤条件，不需要第二套查询，也不会在列表里铺出 N 条同名任务。
- 每次完成写进 `recurrence_completions(rule_id, occurrence_date)`。跨天只是把行上的 `completed`
  换成新一天的状态，历史打卡不受影响，习惯统计从这里算。
- 提醒仍由 `main/reminders.js` 轮询 `tasks.reminder_at` 触发，没有第二套通知系统。
- 法定节假日走 `main/holidays-cn.js` 的离线数据（2026 / 2027 国务院放假 + 调休补班），
  法定连休自动跳过、调休补班的周末自动补上；覆盖年份外降级为周一至周五，不联网拉取。

### 改规则不会重建数据

| 操作 | 影响 |
|---|---|
| 改频率 / 提醒时间 / 完成日 / 起止日 | 只 UPDATE 一行规则 + 重算这一条任务的下一次发生日；打卡历史一律不动 |
| 停止 | 不再排期，任务保留、打卡历史保留；随时可恢复 |
| 跳过本次 | 写 `recurrence_skips`，日期直接推进到下一次发生 |
| 删除规则 | 任务脱钩成普通待办保留，打卡历史清除 |
| 在列表里删除任务 | 整个事项删除（含规则与打卡） |
| 改「重复 10 天」为 8 天 | 只改 `end_date`，任务数始终为 1 —— 这正是旧「预生成实例」模型做不到的事 |

### 习惯打卡

`habit=1` 的规则在任务行显示 💪（普通重复是 🔁），面板给出应发生次数、累计完成、完成率、连续天数与近 30 次明细。
打卡就是勾选任务完成，统计每次打开面板重新读取，格子可点击补打卡 / 撤销。
任何视图勾选完成照旧走 `noteCompletionChange()`，所以「今日已完成」表现与一次性任务一致。

### 兼容旧数据（v17 迁移）

早期版本会为每个发生日预生成一条实例，列表里出现十几条同名任务。v17 迁移把同一规则下的实例合并成一条主任务：
已完成的实例转成 `recurrence_completions` 打卡记录（日期与完成时间保留），其余删除；
主任务的日期 / 提醒 / 完成态由启动后的日切重算。导入旧备份时做同样的合并。
`exportData.schemaVersion` 升到 14，新增 `recurrence_completions` 数组；旧备份缺这些字段时按普通任务还原。

### 边界

- 不做「完成本次后自动生成下一次」的链式待办：只有一条任务按规则反复出现，可以提前看到下一次安排。
- 法定工作日只认离线内置的 2026 / 2027 数据，未覆盖年份按周一至周五处理。
- 规则编辑区是管理面板 / 详情抽屉内的内联区域，不会与设置中心叠成两层弹窗。
