## 分支拓扑：main 与 master 并存（易踩）

- 日常开发都在 `main`；`master` 只多两笔（`add LICENSE.` 与一次 `Merge branch 'main'`），长期落后 20+ 提交。
  **Gitee 默认分支是 `master`**（`origin/HEAD -> origin/master`）→ 只推 main 的话，仓库首页 README 还是旧版。
- `LICENSE`（MIT，201 行）原本只在 master 上，main 里没有，README 却已写 MIT → 已 merge 回 main。
- 现在的约定：**两个分支保持同一提交**，推完 main 顺手把 master 快进（`git branch -f master main`）再一起推。
- 坑：仓库里有 `main/` 目录，`git log main` 会报 `ambiguous argument` → 用 `refs/heads/main` 或 `git log main --`。
- 推私有库用**一次性内联令牌地址**，不写进 `.git/config`；推完 `git update-ref refs/remotes/origin/<branch> <sha>` 同步跟踪引用，否则 `status` 一直显示 ahead。

## 分支收敛：现在只剩 main（上面的「两分支同提交」约定已作废）

- **改 Gitee 默认分支走 API**：`PATCH /repos/{owner}/{repo}`，body 必须带 `name`（真实名 `todoTask`，不是 path `todo-task`），
  否则 400 `name is missing`；带 `default_branch:"main"` 一次成功。**先改默认分支再删 master** —— 10-25 记的
  「Gitee 不允许删除默认分支」只是顺序问题，不是限制。
- 删除顺序：API 改默认 → `git push --delete master` → `git branch -D master`。
- 陈旧引用要手清：`update-ref -d refs/remotes/origin/master`、`symbolic-ref refs/remotes/origin/HEAD refs/remotes/origin/main`，
  否则 `branch -a` 还会显示幽灵分支。
- 本机 `credential.helper=manager-core`（全局）但没装 GCM → 每条网络命令都报
  `git: 'credential-manager-core' is not a git command`，推拉实际靠内联令牌地址；要免输入可改 `wincred` 并把令牌存进 Windows 凭据管理器。
